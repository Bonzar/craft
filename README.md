# craft

Исполняемая часть системы агента Влада: то, что агент запускает и читает файлами.
Логика живёт модулями по разделам «Архитектуры» — раздел устройства системы
отвечает за свой модуль.

## Модель

Репозиторий не ведёт реестр конкретных модулей в README. Каждый модуль сам
описывает себя в `module.toml`: части, события, зависимости от других модулей
и целевые харнесы. Поэтому модуль можно добавить или удалить без правки этого
файла.

Установщик читает эти шапки, раскладывает части в слой выбранного харнеса и
регистрирует его хуки. Правила — обычная часть `rules`: Claude получает их в
свой каталог правил, Codex — в `~/.codex/AGENTS.md` между метками модуля.
Репозиторные `CLAUDE.md` и `AGENTS.md` не дублируют эти правила в контексте.

## Локальный Desktop

Набор включается только в подготовленном Git worktree сессии. При запуске
из обычного checkout модули не исполняются и их контекст не доставляется.

Выбранное окружение Desktop использует `.codex/environments/environment.toml`.
Его setup до первого хода запускает `tools/jarvis-desktop-setup` из текущего
worktree. Скрипт устанавливает туда модули, правила и скиллы, регистрирует
штатное доверие точным командам хуков в активном профиле Desktop и заново
проверяет его через `hooks/list`. Без подтверждённого доверия setup завершается
ошибкой. Маркер готовности `.codex/jarvis/desktop.json` появляется только после
успеха. Ветка нового worktree должна уже содержать этот bootstrap.
Перед доставкой проверяется именно коммит: `python3 tools/check-desktop-release REF`
создаёт чистый checkout и связанный worktree из REF и выполняет его setup
с отдельным профилем Codex. Незакоммиченные файлы не подмешиваются.

Desktop CLI 0.162.0-alpha.17.2 ищет проектные определения хуков linked worktree
в основном checkout — подтверждено нативной пробой, см.
[openai/codex#23996](https://github.com/openai/codex/issues/23996).
Поэтому там хранится только общий вход: одинаковые охраняемые команды.
Перед запуском они проверяют Git worktree, локальный маркер готовности и
наличие локального dispatcher. Сам dispatcher повторно сверяет идентичность
worktree. В основном checkout и неподготовленных worktree команды молчат.
Исполняемые модули, правила и состояние берутся только из текущего worktree.
В глобальном конфиге регистрируется только нативное доверие этим командам.

`codex-rules` доставляет отрендеренные правила локального набора вместе со
снимком Craft уже на первом ходе и после compact. Состояние хуков хранится в
`.codex/state` этого worktree. CLI-обёртка использует отдельный игнорируемый
профиль `.codex/cli`, чтобы не перезаписывать определения Desktop.

## Окружение с нуля

Облачное окружение харнеса держит две вещи, которых в репозитории нет: строку
запуска установщика и секреты. Окружение «Craft», созданное 14.10.2026,
стартовало без них: журнала установки не было, и `env-refresh` промолчал
(замер 14.10.2026). Восстанавливается по шагам ниже.

### Claude Code on the web

1. **Окружение.** Репозиторий `Bonzar/craft`. Сеть пускает `connect.craft.do`
   (Craft), `github.com` (свежесть набора) и `registry.npmjs.org` (клиент
   codex ставит модуль `codex-login`).
2. **Setup-скрипт** — одна строка, прямой вызов установщика:

   ```bash
   python3 /home/user/craft/tools/jarvis-install --harness claude
   ```

   Путь абсолютный: скрипт стартует в `/home/user` при `HOME=/root`, клон
   лежит в `/home/user/craft` (замер 18.09.2026). Репозиторий установщик
   находит от своего пути, переходить в клон не нужно (замер 14.10.2026).
3. **Переменные окружения** — значения в репозиторий не пишутся:

   | Переменная | Откуда взять | Кто читает |
   |---|---|---|
   | `CRAFT_API_BASE` | connect-ссылка Craft вида `https://connect.craft.do/links/‹токен›/api/v1` | `craft-sync`, снимок Craft на старте |
   | `CRAFT_LINKS_STORE` | ID дока «🔧 Служебный: кэши craft-sync»: `f6c150bc-6a3f-13ab-7fe5-4eb92f2a9e3b` | `craft-sync --backlinks` |
   | `CODEX_AUTH_JSON` | содержимое `~/.codex/auth.json` рабочей машины | `codex-login` |
   | `VLESS_URL` | VPN-подписка | туннель смены страны, `CLAUDE.md` |
   | `TAILSCALE_AUTHKEY` | многоразовый эфемерный ключ из панели Tailscale | `tools/mac-tunnel.sh` |
   | `MAC_NODE_ADDR` | tailnet-адрес мака | `tools/mac-tunnel.sh`, `tools/mac/` |

4. **Проверка — новой сессией**, в идущей установка старт уже не повторит:
   `~/.claude/jarvis/installed.json` есть, `~/.claude/rules/` разложен, в
   контексте нулевого хода снимок Craft, а
   `~/.claude/jarvis/modules/codex-login/bin/npm/bin/codex --version` отвечает.

Правка setup-скрипта сама пересобирает снимок окружения.

### Codex

1. **Стартовый скрипт среды** — одна строка до запуска процесса Codex:

   ```bash
   python3 /workspace/craft/tools/jarvis-install --harness codex
   ```

   Пути профиля и состояния установщик берёт из `CODEX_HOME` и
   `JARVIS_STATE_DIR`, подробности и проверка — в разделе «Managed-среда
   Codex» ниже.
2. **Переменные окружения:** `CRAFT_API_BASE` и `CRAFT_LINKS_STORE` из той же
   таблицы. `CODEX_AUTH_JSON` не нужна: свой вход у сессии Codex уже есть.
   Доезжают ли настройки среды до стартового скрипта Codex, не замерено.

### Как устроена установка

При ошибке установки в Claude и Codex сам установщик пишет причину в stderr
и возвращает код 1. Внешний `|| echo` не нужен: он скрыл бы код ошибки.

Установщик запускается **до старта харнеса** — иначе хуки стартового контекста
на первой сессии не встанут, и хуком старта сессии его не заменить. Установщик
идемпотентен: повторный запуск не меняет уже совпадающую раскладку. Внешнюю
зависимость, которую нельзя привезти файловой частью модуля, готовит владелец
этой зависимости через собственный модульный контракт, а общий установщик не
знает её имени.

Переменных из настроек окружения скрипту не достаётся: в сессии они есть, а в
setup-скрипт не приезжают (дамп имён переменных 18.09.2026). Поэтому всё, что
от них зависит, выполняется на событии сессии, а не в setup. Сам setup ставит
модули и базовые исполняемые зависимости харнеса.

Для Codex установщик после записи строк хуков разговаривает с `codex
app-server`, поэтому `codex` должен быть на `PATH`: без доверия Codex хук молча
не исполняет.

Установщик сверяет все пары события и команды, записывает доверие, затем
заново читает `hooks/list`. Пропущенный, выключенный или недоверенный хук,
ошибка native API и недоступный каталог профиля или состояния дают код 1.
Проверка регистрации не запускает хуки и не доказывает доставку их вывода.

Модули из других мест — например, лично-рабочий слой junk на маке — ставятся
рядом с набором craft вторым источником: флаг `--extra-modules <каталог>`
(можно повторять), а без флага — переменная `JARVIS_EXTRA_MODULES`, каталоги
через двоеточие, как в `PATH`. Обёртки запуска передают переменную установщику
своим окружением, поэтому достаточно задать её на машине, где слой есть:

```bash
export JARVIS_EXTRA_MODULES="$HOME/arc-mounts/arcadia/junk/bonzarr/ai/modules"
```

slug уникален во всех источниках сразу. Дополнительные каталоги записываются в
журнал установки, и модуль свежести ставит их снова при догоне `main`. Запуск
без флага и без переменной снимает их модули, как и любые исчезнувшие.

Сборочные модули Codex получают Go и локальные кэши через свой адаптер.
Установщик не скачивает компилятор и не меняет глобальные настройки Go.
Подготовка идёт внутри сборочного хука на старте сессии, до сборки бинарника.

После обновления `main` workflow `publish-codex-dist` проверяет исходники,
собирает контрольную раскладку Cloud и публикует её в `main` отдельного
репозитория `Bonzar/craft-codex-dist`. Подключение публикации, контрольные
суммы и реальный замер описаны в [пробе Cloud из dist](docs/cloud-repository-probe.md).

### Managed-среда Codex

В managed-среде профиль может находиться вне `~/.codex`. Установщик берёт
активный путь из `CODEX_HOME`, явный `--settings-dir` имеет приоритет.
Каталог состояния выбирается по `--state-dir`, затем `JARVIS_STATE_DIR`,
затем домашнему пути. Выбранный путь записывается в журнал установки, и все
хуки этого набора используют его, даже если среда хука отличается.

В стартовом скрипте среды, **до запуска процесса Codex**, нужна команда:

```bash
python3 /workspace/craft/tools/jarvis-install --harness codex
```

Она использует `CODEX_HOME` и `JARVIS_STATE_DIR`, переданные средой. Если
стартовый скрипт выполняется до появления этих переменных, задайте фактические
пути через `--settings-dir` и `--state-dir`: каталог установки должен совпасть
с профилем, который затем читает Codex. Путь к клону тоже берётся из настроек
среды. `/workspace/craft` — путь текущего managed-окружения.

Профиль, установленный набор и состояние сессии должны находиться внутри её
worktree. Это нужно настроить до запуска харнеса. Значение переменной в shell
и отдельный app-server не подтверждают, что облачный агент читает этот профиль.
Путь под read-only mount не подходит для состояния. Изменение переменной
дочерним Python-процессом не меняет среду родительского облачного агента.

Install script готовит опубликованный снимок. По актуальной документации
cloud-environments репозитории могут обновляться без повторного запуска
установки и startup-команд. Поэтому одна строка установки в настройках сама
по себе ещё не подтверждает подготовку перед каждым первым ходом. Нужен
отдельный замер новой сессией настоящего Cloud и после compact. Для изменения
повторно используемой среды документация описывает Edit, Save и Republish.

Установка в уже идущем диалоге восстанавливает файлы, но не повторяет событие
старта и не загружает правила задним числом. Для проверки автоматического
подключения нужна новая сессия: в активном профиле есть разделы модулей в
`AGENTS.md`, `hooks/list` показывает наши строки включёнными и доверенными,
а `start-context.json` в зоне новой сессии содержит обоих поставщиков без
ошибок и полный снимок Craft. После сжатия тот же хук собирает контекст заново.

Сборочные хуки используют `-buildvcs=false`: установленная копия исходников
не требует доступа к Git-метаданным. Саму сборку по-прежнему выполняют модули
на `SessionStart`, а не установщик или стартовый скрипт среды.

## Снимок окружения отстаёт, набор догоняет его на старте

Этот механизм относится к Claude Code on the web. Модуль свежести имеет
`harness = "claude"`. Для Codex Cloud проверка свежести с предупреждением,
без изменения действующего окружения, остаётся отдельной задачей.

Setup-скрипт выполняется один раз — при сборке снимка окружения. Дальше сессии
стартуют из снимка, пропуская скрипт. Пересобирается снимок сам: при правке
скрипта или сетевых хостов и примерно раз в семь дней (дока cloud-environments,
раздел Environment caching, 19.09.2026). Кнопки пересборки нет.

Значит, в облачной сессии расходятся две вещи: код репозитория платформа отдаёт
свежим на каждом старте (рабочий чекаут создаётся в момент старта и стоит на
голове main), а набор модулей в домашнем каталоге остаётся тем, каким его застал
снимок — до недели старым.

Стартовый модуль проверяет, не отстал ли установленный набор от checkout,
собранного для этой сессии. Он обновляет только прямое отставание от `main`, не
откатывает явно выбранную ветку и продолжает старт после обновления. Детали
условий, замеров и границ этого поведения живут в документации
соответствующего модуля и в архитектуре Craft, а не здесь.

## Что живёт в Craft

Файлами не дублируется, читается по ссылкам:

- **Правила базы** — разделы сферы «Личное», вход «Сущность базы #раздел»:
  `blocks get a6784801-9d92-875c-f146-50159368745b --depth -1`, дальше по «Связям».
- **Устройство системы** — разделы сферы «Джарвис», вход «Архитектура #раздел»:
  `blocks get a2efce64-c813-7c06-3ce8-72714bdb545e --depth -1`, дальше по «Связям».
- **Стройка** — проект «Модульная система агента 🤖»:
  `blocks get 9a9b271a-3656-53e3-b933-72500de42db3 --depth 2`.

## Каталоги

- `core/` — исходник ядра общего кода, `modules/` — модули Джарвиса (копию ядра
  установщик кладёт внутрь каждого), `tools/jarvis-install` — установщик.
  Документация — `core/README.md`.
- `data/` — материал, у которого пока нет модуля-хозяина. С появлением хозяина
  он переезжает в его `data/`.
- `evals/` — замеры поведения агента на записанных кейсах. Документация —
  `evals/README.md`.
- `tools/mac/` — инструменты, работающие на маке Влада: домашний выход в сеть,
  настоящее окно браузера, пульт капчи. Документация — `tools/mac/README.md`.
- `.claude/` — скиллы, ревью-агенты и ревью-конвейер для Claude Code.
