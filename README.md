# craft

Исполняемая часть системы агента Влада: то, что агент запускает и читает файлами.
Логика живёт модулями по разделам «Архитектуры» — раздел устройства системы
отвечает за свой модуль.

## Правила агента

Правила, по которым агент работает, лежат частями `rules` модулей и целиком
живут в репозитории:

- `modules/behavior/rules/behavior.md` — как вести ход, спрашивать, показывать и отчитываться.
- `modules/craft-call/rules/craft-tool.md` — механика инструмента Craft: чтение и запись блоков.
- `modules/code/rules/code.md` — правила кода, стек-агностик, с диспетчером доменных страниц.

Правила — это модули из одной части `rules`: хука у них нет, и установщик
раскладывает их туда, где их читает харнес: Claude — `~/.claude/rules/‹slug›/`,
Codex — свой `~/.codex/AGENTS.md`, между метками модуля.

Другого пути в контекст у правил нет. `CLAUDE.md` и `AGENTS.md` репозитория их
больше не импортируют: пока мост стоял, в облачной сессии правила лежали в
контексте дважды — импортом из репозитория и установкой (замер 18.09.2026).
Значит, без установщика правил в сессии не будет вовсе — как он ставится в
облаке, ниже.

## Установка модулей в облачной сессии

Установщик запускается **до старта харнеса** — иначе хуки стартового контекста
на первой сессии не встанут. В облачном окружении (Claude Code on the web) это
делает setup-скрипт окружения, в его настройках:

Скрипт выполняется не в корне клона: он стартует в `/home/user`, а `HOME` у
него `/root`. Клон лежит в `/home/user/craft`, поэтому путь к нему абсолютный,
а не через `$HOME` (замер 18.09.2026):

```bash
# репозиторий уже склонирован окружением; скрипт стартует в /home/user
if [ -f /home/user/craft/tools/jarvis-install ]; then
  cd /home/user/craft
  python3 tools/jarvis-install --harness claude    # или --harness codex
  mkdir -p "$HOME/.local/bin"
  (cd craft-sync && CGO_ENABLED=0 go build -ldflags="-s -w" -o "$HOME/.local/bin/craft-sync" .)
else
  echo "jarvis-install не найден: модули в этой сессии не поставлены" >&2
fi
```

Внутри условия ставится сам набор модулей и `craft-sync`: бинарник в
контейнере не предустановлен и пересоздание контейнера не переживает, а
поставщик `craft-snapshot` без него отдаёт пустой текст и пишет причину в
журнал сессии. Установщик идемпотентен: повторный запуск ничего не меняет.

Три мелочи, на которых скрипт уже спотыкался (замеры 18.09.2026):

- без перехода в клон запуск `python3 tools/jarvis-install` падает на «нет
  файла», и сессия стартует вообще без модулей — молча, если не написать
  причину в stderr;
- `go build ./craft-sync` из корня не работает: `go.mod` лежит в самом
  `craft-sync/`, и из корня Go отвечает «cannot find main module». Поэтому
  сборка идёт подоболочкой из каталога пакета;
- каталог `$HOME/.local/bin` в свежем контейнере может не существовать, а
  `go build` его сам не создаёт.

Переменных из настроек окружения скрипту не достаётся: в сессии они есть, а в
setup-скрипт не приезжают (дамп имён переменных 18.09.2026). Поэтому всё, что
от них зависит, живёт не в скрипте, а в старте сессии: `CRAFT_API_BASE` читает
поставщик `craft-snapshot`, а вход Codex из `CODEX_AUTH_JSON` раскладывает в
`~/.codex/auth.json` модуль `codex-login`. Самому скрипту переменные не нужны —
он ставит модули и собирает `craft-sync`, а там, где `codex` не предустановлен,
ставит и клиент (`npm i -g @openai/codex`).

Для Codex установщик после записи строк хуков разговаривает с `codex
app-server`, поэтому `codex` должен быть на `PATH`: без доверия Codex хук молча
не исполняет.

## Что живёт в Craft

Файлами не дублируется, читается по ссылкам:

- **Правила базы** — разделы сферы «Личное», вход «Сущность базы #раздел»:
  `blocks get a6784801-9d92-875c-f146-50159368745b --depth -1`, дальше по «Связям».
- **Устройство системы** — разделы сферы «Джарвис», вход «Архитектура #раздел»:
  `blocks get a2efce64-c813-7c06-3ce8-72714bdb545e --depth -1`, дальше по «Связям».
- **Стройка** — проект «Модульная система агента 🤖»:
  `blocks get 9a9b271a-3656-53e3-b933-72500de42db3 --depth 2`.

## Каталоги

- `core/` — исходник ядра общего кода, `modules/` — модули Джарвиса (копию ядра
  установщик кладёт внутрь каждого), `tools/jarvis-install` — установщик.
  Документация — `core/README.md`.
- `data/` — данные для модулей, отдельно от кода: `data/shell/` — списки и кейсы
  разбора команд оболочки, `data/locks/` — материал для замков.
- `craft-sync/` — CLI на Go для чтения пространства Craft через connect-API:
  детект изменений, бэклинки и чтение текста блока (`--markdown`, им живёт
  поставщик стартового контекста). Документация — `craft-sync/README.md`.
- `evals/` — замеры поведения агента на записанных кейсах. Документация —
  `evals/README.md`.
- `tools/mac/` — инструменты, работающие на маке Влада: домашний выход в сеть,
  настоящее окно браузера, пульт капчи. Документация — `tools/mac/README.md`.
- `.claude/` — скиллы, ревью-агенты и ревью-конвейер для Claude Code.
