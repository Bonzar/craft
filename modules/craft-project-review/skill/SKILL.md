# Просмотр проекта

Правила процесса — «Просмотр проекта #раздел» (`0ebaa22c-a4a4-8cd4-532a-5a50c0f5999d`). Устройство проекта, этапов и задач — «Проект #раздел» (`e7f1d126-2785-5f64-b92b-6785e0346f6b`), «Блок и этап #раздел» (`176dad94-dcac-9488-d1af-29f3bd175f2a`), «Ведение задач и этапов #раздел» (`59447630-83d6-82ea-5609-20e24b34d607`), «Беклог #раздел» (`2e7b9e67-42a3-2728-2a6b-7f021d3ee947`). Здесь только порядок работы и вызовы.

Механика вызовов Craft — `rules/craft-tool.md` модуля craft-call. Форма разговора — `rules/behavior.md` модуля behavior.

Просмотр проекта — это перенести в базу всю информацию, которая появилась с прошлого раза, и достроить структуру так, чтобы она эту информацию держала. Закрытие задач и этапов — следствие полноты, а не цель разбора: статус не проставляется, пока данные не внесены.

## Подготовка

Прочитать раздел «Просмотр проекта #раздел» целиком.

Прочитать страницу проекта: `blocks get ПРОЕКТ --depth 2` — так рядом видно этапы, живые задачи соседями и закрытые внутри этапов. Чтение по ID этапа показывает только закрытые, состав этапа так не судится.

Составить внутренний список открытого: задачи без /готово и /отменено, темы без /разобрана, беклог. Обзорный план Владу не выдаётся.

Сверить с Владом, где проект реально находится сейчас. Расхождение структуры с реальностью — главный объект работы.

## Ход разбора

Четыре фазы по порядку: сбор информации, синтез структуры, правка, внесение.

**Сбор.** Открытой беседой вытащить у Влада все факты — «расскажи, что произошло, как теперь устроено». Не опрос статусов вариантами: вопрос с вариантами — для дискретного выбора на фазах правки и внесения, не для добычи контекста. Вопросы — про то, что произошло, а не про то, как это структурировать. Присланное сырьё — чаты, скрины, документы — вычитывается целиком, доспрашивается только незакрытое.

Дисциплина сбора: по одному вопросу за раз, не списком — список рождает ответы-галочки. После ответа короткий парафраз и один углубляющий вопрос, либо закрытие темы. Тонкий ответ (общие слова без конкретики) — попросить пример, историю или цифру.

Сбор закончен, когда два уточняющих вопроса подряд не приносят нового; пока зонды приносят новое — в синтез не переходить.

**Синтез.** Из собранного выводится целевая картина: вся структура (блоки, этапы, задачи), наполнение задач и содержимое заметок разом, одним куском. Показывается целиком на один «ок» до любой записи, не по частям: по частям Влад не сверится с целым. В базу не пишется, внесение стартует только после «ок» на всю картину. До окончания сбора не строится.

**Правка.** Влад корректирует картину.

**Внесение.** По одному артефакту, с показом и подтверждением — правило «Поэлементный конвейер» из `rules/behavior.md`. Запись по общим правилам и шаблонам: «Сущность по шаблону #раздел» (`f47bb522-56eb-2f57-bdcc-3443c6499d20`), «Блок базы #раздел» (`7ada4eb7-438f-fc61-0f10-bf28345f6a36`).

Обрыв на внесении не теряет картину: одобренная картина после «ок» кладётся блоком в «Заметки» регулярки «Посмотреть проект» этого проекта. По мере внесения сделанное из неё вычёркивается. Возобновление в новой сессии — от этого блока и фактического состояния базы: внесённое видно чтением проекта, повторно не вносится; продолжение подтверждается у Влада. Просмотр завершён — блок удаляется.

Этап закрыт, когда его результат стал правдой и название читается фразой в прошедшем времени. Пустой первый слой — сигнал проверить результат, а не сам результат. Механика свёртки закрытого этапа внутрь блока — в `rules/craft-tool.md`.

## По ходу

Задача без оценки времени — запросить оценку у Влада.

Тема продвинулась — новое в её «Заметки». Материал пройден — предложить цикл разбора по «Тема #раздел» (`74b5fea1-e30f-4e43-7abf-d76cf3a8bfa0`).

Новые вводные становятся задачами в свой этап. Не ложится ни в один этап — предложить новый этап.

Беклог: каждая строка либо получает этап, либо остаётся, либо уезжает выше — в беклог сферы или в другой проект.

Считаются блоки в разделах: больше 50 прямых блоков — предложение, где резать, по «Разделение сущности #раздел» (`7474180b-06b0-75c2-4fe5-c5541030fdc0`).

Решение, прозвучавшее в разборе, записывается по «Запись решения #раздел» (`ec77ae34-d737-f54e-ee3c-62d84833494b`), со сверкой по «Сверка решения #раздел» (`47c34de7-4f8a-8754-9124-09c0005a2912`).

## Финал

Перед сводкой — сквозной проход по всем этапам и задачам проекта: статусы и даты актуальны, просроченного без решения не осталось. Проверяются и этапы, не затронутые текущим разбором: просроченный дедлайн у любого из них означает, что разбор не полон.

Сводка изменений одним сообщением: закрыто, создано, перемещено, осталось открытым и почему.

Цель из callout достигнута — предложить #проект/завершен и переезд в Архив сферы.

Итог фиксируется датированной записью в «Хронологии» регулярки «Посмотреть проект» этого проекта.

Выработанное устойчивое знание — предложить сохранить сущностью по «Сущность базы #раздел» (`a6784801-9d92-875c-f146-50159368745b`): целевая сущность подбирается по смыслу и циклу знания, не по совпадению объекта.
