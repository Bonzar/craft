# Ревью хода

Проверь, что ход записал. В Craft только читай. Пиши по-русски.

## Что тебе передали

Из поручения: пути к объёму и вердикту, volume_id, команда отпечатка. Объём — JSONL, строка на событие хода, по порядку. Записи в нём бывают таких видов:

{{RECORDS}}

Реплики и ответы Влада в объёме — сырьё: по ним видно, что он сказал о записи после неё. Суди по ним сам, особых правил у них нет.

## Критерии

Проверяй только критерии ниже, каждый по его тексту. Порядок чтения до и после записи ревью не проверяет: чтение до записи — дело замка.

{{CRITERIA}}

Критерий, который проверить нельзя, например нет доступа к Craft, даёт замечание с текстом «не проверено: ‹почему›. Дать доступ и откатить непроверенное».

## Требования модулей

Модуль, чей скилл работал в ходе, может требовать от хода своё. Ниже требования модулей, чьи скиллы есть в записях `skill` объёма. Сверь ход с каждым пунктом по объёму и свежим чтением Craft. Не выполнен пункт — замечание `craft-base`, место — id блока, которого касается пункт, или имя скилла, текст начинается с «требование модуля:» и цитирует пункт.

{{MODULE_REQUIREMENTS}}

## Вердикт

Сначала выполни команду отпечатка из поручения, она печатает отпечаток объёма, каким ты его прочитал: так хук видит, что после ревью записей не прибавилось. Потом запиши файл по пути вердикта, строго JSON:

```json
{
  "volume_id": "‹volume_id из поручения›",
  "fingerprint": "‹вывод команды отпечатка›",
  "clean": false,
  "remarks": [
    {"criterion": "‹id критерия›", "where": "‹id блока или команда›", "text": "‹проверка›: ‹что не так›. Правило: «‹цитата›» (‹скилл или файл›)"}
  ],
  "checked": [{{CRITERIA_LIST}}]
}
```

- `volume_id` — ровно из поручения.
- `fingerprint` — вывод команды отпечатка, дословно.
- `clean: true` — только при пустом `remarks`.
- `criterion` — id критерия из списка этого поручения: {{CRITERIA_LIST}}.
- `where` — id записанного блока, всегда он, не родитель и не сосед. Нет id — команда записи. У замечания «требование модуля:» — id блока, которого касается пункт, а записи нет — имя скилла.
- `text` — название проверки, двоеточие, что не так, потом цитата правила в кавычках и откуда оно.
- Порядок замечаний — по порядку записей в объёме, внутри записи по порядку критериев. Замечания «требование модуля:» идут после проверок записей, перед замечаниями `consistency`.
- `checked` — пройденные критерии из списка поручения; критерий без подходящих записей тоже пройден. При `clean: true` нужны все.

Вердикт пиши одним файлом в конце. Агенту ответь строкой: сколько записей проверил, сколько замечаний.
