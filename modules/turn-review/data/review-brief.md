# Ревью хода

Проверь, что ход записал в Craft. В Craft только читай.

## Что тебе передали

Из поручения: пути к объёму, вердикту и файлу типов, volume_id, число записей `write`. Объём — JSONL, строка на событие хода, по порядку:

- `write` — запись: `command`, `result`, `types` — теги типа;
- `read` — чтение: `command`, `ids` прочитанных блоков;
- `skill` — вызов скилла;
- `anchor` — якорь сессии.

Файл типов — JSON: `types`, тег → `{"skill": ‹скилл›}`.

## Критерий «craft»

Для каждой записи `write`:

1. По тегам из `types` найди скилл в файле типов. Прочитай `{{HARNESS_SETTINGS}}/skills/‹скилл›/SKILL.md` целиком. Сверяй по разделам, какие в нём есть: «Шаги записи», «Заведение», «Закрытие и отмена», «Проверить перед…», «После записи». Разделы у скиллов разные, нет раздела — не замечание. Тегов нет — читай `{{HARNESS_SETTINGS}}/skills/craft-call/SKILL.md` и файл механики, на который он ссылается.
2. Найди id блока в `result` или `command`. Прочитай блок и его родителя через `mcp__‹сервер›__craft_read`: `blocks get ‹id› --depth -1`.
3. Сверь блок с требованиями скилла. Расхождение — замечание `craft`.

## Критерий «links»

Для записи, чей родитель — тоггл «Решения», «Решения проекта» или «Решения сферы».

1. Прочитай «Связи» страницы, где лежит тоггл.
2. Собери id из «Связей» и родителей страницы до корня. Сверь их с `ids` записей `read`, стоящих в объёме раньше этой записи. Непрочитанный id — замечание `links`.
3. Сверь решение по смыслу с «Описанием» и «Решениями» страницы, её родителей и «Решениями проекта» или сферы. Противоречие — замечание с цитатой старого решения.

## Критерий «anchor»

В объёме нет записи `anchor` — замечание `anchor`, место `сессия`, текст «у сессии нет якоря».

## Вердикт

Запиши файл по пути вердикта, строго JSON:

```json
{
  "volume_id": "‹volume_id из поручения›",
  "writes": 2,
  "clean": false,
  "remarks": [
    {"criterion": "craft", "where": "‹id блока или команда›", "text": "‹что не так›"}
  ],
  "checked": ["craft", "links", "anchor"]
}
```

- `volume_id` — ровно из поручения.
- `writes` — число строк `write` в объёме, каким ты его прочитал: так хук видит, что после ревью записей не прибавилось.
- `clean: true` — только при пустом `remarks`.
- `where` — id блока, нет id — команда записи.
- `text` — коротко, с цитатой правила или решения.
- `checked` — пройденные критерии, только из этих трёх; критерий без подходящих записей тоже пройден. При `clean: true` нужны все три.

Не смог прочитать блок или родителя — замечание `craft`. Вердикт пиши одним файлом в конце. Агенту ответь строкой: сколько записей проверил, сколько замечаний.
