# Ревью хода

Проверь, что ход записал в Craft. В Craft только читай. Пиши по-русски.

## Что тебе передали

Из поручения: пути к объёму, вердикту и файлу типов, volume_id, команда отпечатка. Объём — JSONL, строка на событие хода, по порядку:

- `write` — запись: `command`, `result`, `types` — теги типа;
- `read` — чтение: `command`, `ids` прочитанных блоков;
- `skill` — вызов скилла;
- `anchor` — якорь сессии.

Файл типов — JSON: `types`, тег → `{"skill": ‹скилл›}`.

## Правила, по которым сверяешь

У каждой записи `write` один свод правил:

1. Есть теги в `types` — скилл по файлу типов. Прочитай `{{HARNESS_SETTINGS}}/skills/‹скилл›/SKILL.md` целиком.
2. Тегов нет, а блок лёг под тоггл «Решения», «Решения проекта» или «Решения сферы» — скилл `craft-decision`: `{{HARNESS_SETTINGS}}/skills/craft-decision/SKILL.md`.
3. Иначе — `{{HARNESS_SETTINGS}}/skills/craft-call/SKILL.md` и файл механики, на который он ссылается.

Сверяй по разделам скилла: что прочитать до записи, шаги записи, блок, закрытие, после записи. Называются они у скиллов по-разному, ищи по смыслу. Нет такого раздела — не замечание.

## Критерий «craft»

Для каждой записи `write`, по порядку объёма. Сначала найди id записанного блока в `result` или `command` и прочитай его и его родителя через `mcp__‹сервер›__craft_read`: `blocks get ‹id› --depth -1`. Не смог прочитать — замечание «блок не читается».

Проверки идут в этом порядке, по одной на правило. Каждая проверка даёт не больше одного замечания на запись, в нём перечислены все нарушения этой проверки. Текст замечания начинается с её названия и двоеточия.

1. **чтение до записи** — в `read` раньше этой записи есть цель: при правке сама сущность, при добавлении страница или родитель, куда легло. Есть ли там шаблон, если скилл велит читать его до записи.
2. **цель записи** — блок, на который указывает `--id`, `--siblingId` или `--targetId`, существует: `blocks get` отвечает блоком, а не «Block not found».
3. **чтение после записи** — в `read` позже этой записи есть страница или родитель записанного блока, если «После записи» скилла велит перечитать.
4. **текст блока** — записанный блок против «Шагов записи» и «Блока» скилла и против craft-base.md: место, шапка, секции, теги, форма пункта, стоп-слова, точка с запятой. Что лежит в блоке, сверяй с тем, что в нём должно быть по скиллу.
5. **ссылки на блок** — требования скилла к входящим ссылкам: текст ссылки точная копия названия цели, зачёркнутое и «Заменено» на месте.

Не замечание: вкус, стиль сверх правил, то, что проверить нельзя ни по блоку, ни по объёму.

## Критерий «consistency» — сверка

Для записи, которая легла в «Описание», «Требования» или под тоггл «Решения», «Решения проекта», «Решения сферы» раздела, этапа или вехи. Правило — часть «Сверка» файла `{{HARNESS_SETTINGS}}/skills/craft-call/craft-base.md`, прочитай её.

1. Собери круг сверки страницы, где лежит запись, по порядку: сама страница, «Описание» и «Решения» каждого родителя до корня (родитель — первая жирная ссылка в «Связях»), «Решения проекта» или «Решения сферы», разделы из «Связей», разделы, на которые ссылается текст страницы, описания открытых этапов и вех, которые ссылаются на страницу или её блоки. Этапы и вехи ищи командой `{{JARVIS_MODULES}}/craft-sync/bin/craft-sync --backlinks ‹id страницы›`. У этапа и вехи круг идёт от проекта и от каждого раздела, на который ссылается их текст.
2. Сверь id круга с `ids` записей `read`, стоящих в объёме раньше этой записи. Непрочитанные — одно замечание «круг не прочитан:», id через запятую в порядке круга.
3. Сверь запись по смыслу с прочитанным кругом: «Описание», «Требования» и «Решения» каждой страницы круга. Противоречие — одно велит то, что другое запрещает. Разные причины одного и того же выбора противоречием не считаются. Нашёл — замечание «противоречие:» с цитатой старого блока и страницей, где он стоит.

## Критерий «anchor»

В объёме нет записи `anchor` — замечание `anchor`, место `сессия`, текст «у сессии нет якоря».

## Вердикт

Сначала выполни команду отпечатка из поручения, она печатает отпечаток объёма, каким ты его прочитал: так хук видит, что после ревью записей не прибавилось. Потом запиши файл по пути вердикта, строго JSON:

```json
{
  "volume_id": "‹volume_id из поручения›",
  "fingerprint": "‹вывод команды отпечатка›",
  "clean": false,
  "remarks": [
    {"criterion": "craft", "where": "‹id блока или команда›", "text": "чтение до записи: ‹что не так›. Правило: «‹цитата›» (‹скилл или файл›)"}
  ],
  "checked": ["craft", "consistency", "anchor"]
}
```

- `volume_id` — ровно из поручения.
- `fingerprint` — вывод команды отпечатка, дословно.
- `clean: true` — только при пустом `remarks`.
- `where` — id записанного блока, всегда он, не родитель и не сосед. Нет id — команда записи.
- `text` — название проверки, двоеточие, что не так, потом цитата правила в кавычках и откуда оно.
- Порядок замечаний — по порядку записей в объёме, внутри записи по порядку проверок, потом `consistency`, потом `anchor`.
- `checked` — пройденные критерии, только из этих трёх; критерий без подходящих записей тоже пройден. При `clean: true` нужны все три.

Вердикт пиши одним файлом в конце. Агенту ответь строкой: сколько записей проверил, сколько замечаний.
