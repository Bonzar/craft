# Актуализация памяти

Память агента — кэш фактов о жизни Влада со ссылками на источники. Её снимок модуль craft-snapshot подставляет в стартовый контекст каждой сессии. Этот скилл держит снимок свежим: находит страницы сфер, изменившиеся с прошлого прогона, и вписывает новое в кэши.

Механика вызовов Craft — `{{HARNESS_SETTINGS}}/skills/craft-call/craft-tool.md`. Правила текста и ссылок — `{{HARNESS_SETTINGS}}/skills/craft-call/craft-base.md`.

## Константы

- Роутер памяти: `e8132891-81f4-2d63-36f1-d3623d0147b6`.
- Регенерируемая память — подстраница роутера `604c8d7f-fa8f-fa6c-1064-4e3aa47a8823`: «Общий контекст», «Индекс памяти», доменные кэши-подстраницы и «⚙️ Служебное».
- Отметка прошлого прогона — одно значение UTC RFC3339 в код-блоке секции «⚙️ Служебное».
- Папка обхода — «Сферы» `CBD2DF82-F9D1-492A-B2BE-CF91560B5F24` со всеми подпапками.
- Подпапка «Память для агента» `8ecf6df8-0de5-62c7-591b-1a772c80dc5f` не обходится: там роутер, кэши и служебные доки.
- Документ-призрак «[Untitled]» `F5DCF12D-D0F3-40C4-B7DC-1C51955F0E94` отвечает 404, идёт в `--exclude`.
- Детектор изменений: `{{JARVIS_MODULES}}/craft-sync/bin/craft-sync`, базовый URL — env `CRAFT_API_BASE`.

Нет бинарника или `CRAFT_API_BASE` — работа не начинается: одной строкой сказать, чего нет, и остановиться.

## Признак рутины

`JARVIS_AUTONOMOUS=1` в окружении — прогон идёт без Влада. Тогда правки к источникам только перечисляются в отчёте, ничего не применяется и вопросов кнопками нет.

## Шаг 1. Отметка прошлого прогона

`blocks get e8132891-81f4-2d63-36f1-d3623d0147b6 --depth 2`, из «⚙️ Служебное» берётся значение код-блока. Значения нет — `2000-01-01T00:00:00Z`, в выборку попадёт всё.

## Шаг 2. Корневые id сфер

`folders list`, затем `documents list --folder ПАПКА` по «Сферам» и каждой подпапке до дна, кроме «Памяти для агента». Итог — корневые id документов через запятую, без призрака. Глубокий обход блоков делает craft-sync, а не агент.

## Шаг 3. Детект изменений

1. Засечь новую отметку: `date -u +%Y-%m-%dT%H:%M:%SZ`. Её запишет шаг 9.
2. Запуск:

```bash
{{JARVIS_MODULES}}/craft-sync/bin/craft-sync --base "$CRAFT_API_BASE" \
  --docs ‹id шага 2› --exclude F5DCF12D-D0F3-40C4-B7DC-1C51955F0E94 \
  --since ‹отметка шага 1› --incremental --tree
```

craft-sync печатает деревом только изменившиеся и новые страницы — id, название, дата, вложенность отступом — и строку сводки `Changed pages | unchanged | total | scanned | skipped`. Недоступные документы идут строками `! error:`, они попадают в отчёт. Изменений нет и ошибок нет — отчёт «Всё актуально», отметка обновляется, прогон окончен.

## Шаг 4. Чтение изменившегося

Каждая страница из вывода читается по id: `blocks get ID --depth 3`. Страницы без изменений не читаются. Изменился крупный контейнер, проект или сфера, — его изменившиеся подстраницы craft-sync вернул отдельными строками, читаются только они.

Объём изменившегося больше 240 тысяч знаков — документы идут по одному: прочитал, записал кэш, взял следующий. Отметка двигается только тогда, когда обработан весь список. Не успел — шаг 9 пропускается, отчёт называет остаток, следующий прогон возьмёт его по старой отметке.

## Шаг 5. Целевой кэш

Каждый прочитанный документ ложится в доменный кэш по теме: Работа, Здоровье и быт, Отношения и личное, Путешествия, Система агента. Id кэшей видны в прочитанном роутере.

Структура кэшей меняется по ходу:

- кэш перерос 50 прямых блоков — делится по смыслу на под-подстраницу или новый кэш;
- тема не ложится ни в один кэш — новый кэш подстраницей памяти, не документом папки;
- тема ушла в архив или удалена — её факты из кэша убираются;
- два маленьких кэша про близкое — сливаются.

Любая смена состава кэшей правит «Индекс памяти».

## Шаг 6. Сверка с правилами

Каждый прочитанный документ сверяется с правилами своего типа: скилл по тегу — craft-task, craft-stage, craft-section, craft-note — и `craft-base.md`. Сверка сплошная: каждый пункт правил, а не то, что бросилось в глаза. Родитель в шапке и «Связях» означает принадлежность, а не соседство. Сверяется то, что видно на прочитанной глубине, глубже ради сверки не читается.

Частые расхождения: закрытая задача не зачёркнута в «Задачах», связь в одну сторону, текст вне секций шаблона, тег типа не тот или пропущен, секции не по шаблону, битая ссылка.

Каждое расхождение копится в список правок: ссылка на блок, что не так, какое правило, как исправить. Источники актуализация не правит.

## Шаг 7. Запись в кэш

Кэш читается целиком перед правкой: `blocks get ID --depth 3`.

- Карта источников строится только из обхода. Старое содержимое кэша — то, что переписывается, а не список того, что есть: однажды так потеряли проекты, лежавшие отдельными документами.
- Про тему уже есть раздел — новое вписывается в него, устаревшее правится, дубли убираются. Факты из других источников остаются.
- Раздела нет — новый абзац в подходящей по смыслу секции кэша.
- Абзац — отдельный блок в одно-четыре предложения, одна тема на абзац.
- Длинные однотипные множества — одна сводка: объём, устройство, два-три свежих примера, ссылка на источник.
- Ссылкой подкреплено большинство утверждений, и стабильные факты тоже: статусы, ждущие задачи, планы, имена, договорённости.
- Ссылка стоит на словах самой фразы: на сущность — её точное название с тегами, на факт — слова, которые его несут.
- Ссылка ведёт на блок, который несёт факт: этап, раздел, тезис, а не корень сферы. Отдельного блока нет — ближайший содержательный. Id блоков — чтением источника с `--fetchMetadata --format json`.

После правки кэш перечитывается и чинится в том же прогоне:

- нет двух блоков об одном;
- нет наноса истории: блоки-пополнения с датами схлопнуты в сводку;
- прямых блоков не больше 50;
- ссылки целы.

## Шаг 8. Роутер

- «Индекс памяти» правится, только когда меняется состав кэшей.
- «Общий контекст» — сквозное по всем сферам: кто Влад, главные приоритеты и обстоятельства, как с ним говорить. Новое добавляется, изменившееся правится, ушедшее убирается. Коротко, без дублей кэшей.
- Пишется только внутрь регенерируемой памяти. Заголовки «# Общий контекст», «# Индекс памяти», «# ⚙️ Служебное» не меняются.

## Шаг 9. Новая отметка

`blocks update` код-блока «⚙️ Служебное»: отметка, засечённая на шаге 3, одно значение. Время начала обхода, а не конца: правки во время прогона попадут в следующий.

## Шаг 10. Правки к источникам

Список шага 6 пуст — шаг пропускается.

С Владом — правки по документам, у каждой ссылка, что не так, правило и исправление. Что применять, спросить {{ASK}}. Применяется только выбранное, по скиллу типа источника.

В рутине — только список в отчёте.

## Шаг 11. Отчёт

Перед отчётом — самопроверка свежим чтением:

- код-блок «⚙️ Служебное» несёт отметку шага 3, кроме случая, когда шаг 9 пропущен по остатку;
- изменения были — затронутые кэши несут вписанное.

Не сходится — прогон не завершён, и в отчёте это блокер, а не примечание.

«Актуализация завершена» и:

- сколько документов проверено, сколько без изменений, сколько сводок обновлено;
- какие кэши обновлены и чем, ссылками;
- смена состава кэшей, если была;
- недоступные документы из `errors`;
- список правок к источникам, если не пуст.
