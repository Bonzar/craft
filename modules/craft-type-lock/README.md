# craft-type-lock

Замок «запись в тип сущности без его скилла». Агент не запишет в Craft
сущность с тегом типа, пока в этом ходе не вызвал скилл этого типа. Решение
тега не несёт, его замок узнаёт по месту: запись под тоггл «Решения» без
скилла craft-decision тоже не пройдёт.

## Что ловит

Вызов `craft_write` и `craft_write_and_show` сервера Craft MCP, в команде
которого есть тег типа. Второй инструмент исполняет те же команды, что и
первый, поэтому закрыт тоже. Инструмент узнаётся по хвосту имени
(`mcp__‹сервер›__craft_write`): имя сервера зависит от того, как Craft
подключён, и замок от него не зависит.

Тег ищется по всей строке команды: в `--markdown`, в JSON после `--json`, в
пачке через `;`. Тег с хвостом тоже тег: `#задача/готово`, `#этап/отменено`.
Слово, которое только начинается как тег (`#задачами`), тегом не считается.
Регистр не важен: `#Задача` — тот же тег. Кириллица, записанная в JSON как
`\uXXXX`, разворачивается перед поиском.

Текст ссылки на блок (`[Сборка #этап](block://…)`, то же с `craftdocs://`)
из поиска вырезается. Текст ссылки — копия имени цели с её тегами, поэтому
такие ссылки есть почти в каждой записи: у задачи проекта — ссылка на этап,
у этапа — ссылки на разделы. Ссылка цель не пишет, и скилл цели для неё не
нужен.

Какой тег какой скилл требует — `data/types.json`, поле `types`, у каждого
тега `skill`. Больше там ничего нет: id разделов и шаблонов типа живут в
`skill/SKILL.md` самих скиллов.

Нет вызова скилла этого типа в текущем ходе — запрет. В причине: какой тег
найден, какой скилл вызвать, и что после вызова запись надо повторить. Скилл
вызван — замок молчит, кроме первого отказа API за сессию, о нём текст в
ход.

## Решение узнаётся по месту

Тега у решения нет, по тексту команды его не отличить от любого другого
блока. Место замок берёт из connect-API Craft (`CRAFT_API_BASE`), и это его
единственный поход в сеть, только на записи в Craft.

Родителя блока connect-API не отдаёт. Поэтому замок помнит страницы, которые
агент читал в сессии: id из команды `craft_read` и id страниц из её ответа
(`<page id="…">`, так запоминается заметка дня, прочитанная по дате), до
двадцати последних, свежие первыми. На записи он запрашивает их заново на
глубину 2, свежие первыми, и ищет среди блоков цели записи: id из `--id`,
`--ids`, `--siblingId`, `--targetId`, `--targetSiblingId` в любом месте
команды, через пробел или «=», кавычки вокруг id сняты. Страницы идут, пока
не найдены все цели: решение, когда любая из них под «Решениями». Глубина 2
нужна этапу: его решения лежат внутри блока этапа, а этап читается со
страницы проекта. Решение на вложенной странице глубже второго уровня на
чтении проекта не видно: его страницу агент читает сам, до записи.

Где окажется запись: после соседа по `--siblingId` и `--targetSiblingId`,
при `--position before` рядом с предыдущим блоком, у `blocks add --id` и
`blocks move --targetId` в конце детей родителя, при `before` в начале, у
остальных флагов это сам блок. Блок под
«Решениями», когда от него назад первый блок без отступа — тоггл «Решения»,
«Решения проекта» или «Решения сферы». Так ловятся запись после тоггла,
после любого решения, перед разделителем сразу за решениями, правка и
перенос самого решения, перенос чужого блока под решения.

Цели нет ни на одной прочитанной странице или чтений в сессии не было —
запись в непрочитанное, и замок её запрещает: по механике Craft страница
цели читается до записи, а что агент читал, замок видит сам. В причине —
команда чтения, после которой запись надо повторить.

Когда замок судить о месте не может и ход в этом не виноват, место не
судится, а проверка по тегам идёт как обычно: без скилла типа запись всё
равно под запретом. Два случая. У команды с целью (`blocks
add/update/move/delete`, `tasks update`) не разобран ни один id или часть —
молчание, причина в следе содержит «место записи не проверено». Отказ
окружения: нет `CRAFT_API_BASE`, API не ответил или проверка не уложилась в
12 с — в первый раз за сессию текст в ход с той же причиной, на пропуске и
на запрете по тегу; дальше молчание с причиной в следе. stderr хука до
модели не доходит (замер 01.11.2026), поэтому текст, а не stderr.

Регистр id API различает: документ с id в верхнем регистре на id в нижнем
отвечает 404, и наоборот (замер 01.11.2026). Поэтому id хранятся и
запрашиваются как есть, сравниваются без учёта регистра, id из ответа
чтения идёт впереди id из команды, а 404 повторяется в другом регистре.

Разобранные цели при неразобранных судятся: `blocks move --id ‹решение›
--targetSiblingId ЗАДАЧА` запрещён без craft-decision. Лишний запрет
остановил бы верную запись, а решение без скилла поймает ревью хода.

Цена: на каждую запись в Craft с id цели один запрос к API на прочитанную
страницу, обычно один, в худшем случае до двадцати в пределах 12 с. Без
User-Agent connect-API отвечает 403 (замер 01.11.2026), поэтому запрос идёт
с заголовком.

Суждение о месте живёт в `hooks/place.py`, точка входа `hooks/module.py`
его импортирует.

## Что не ловит

- Запись без тега типа на прочитанной странице и не под «Решениями»: правку
  текста блока, таблицы, коллекции, покупки. Замок молчит и пишет в след
  «тега типа нет». Та же запись в цель, которой нет среди прочитанных
  страниц, запрещается как запись в непрочитанное.
- Запись без id цели вовсе: `tasks add --help`, команды коллекций. Замок
  молчит, в следе «тега типа нет».
- Запись по id без текста тега: закрытие через `tasks update --id … --state
  done`, `blocks move` закрытой задачи или этапа, `blocks delete`, тело задачи
  отдельными блоками через `blocks add --id ЗАДАЧА`. Тега в команде нет —
  скилла типа замок не требует, хотя правила закрытия и переноса живут в
  скиллах. Место при этом проверяется: цель на прочитанной странице и не под
  «Решениями» — молчание, цели среди прочитанных нет — запрет.
- Справку без тега: `tasks add --help`. Справку с тегом в команде замок
  проверяет как запись: `--help` в полезной нагрузке иначе открывал бы замок.
- Чтение: `craft_read` замок не блокирует, только запоминает id прочитанных
  страниц в `craft-type-lock.json`, поле `reads`.
- Запись из Codex. Обёртка Codex пока знает только старт и сжатие, событий
  `pre-tool`, `post-tool` и `prompt` у неё нет. Установщик ставит замок и
  туда, но предупреждает: в Codex он не сработает.

## Как устроен ход

Ход — от реплики до реплики. Счёт хранит сам замок:

- реплика (`prompt`) — номер хода растёт на 1;
- вызов инструмента `Skill` (`post-tool`) со скиллом типа — скиллу пишется
  номер текущего хода. Имя скилла с префиксом плагина (`плагин:craft-task`)
  берётся по части после последнего двоеточия;
- запись в Craft (`pre-tool`) — каждый скилл найденных тегов должен нести
  номер текущего хода, и craft-decision тоже, когда запись ложится под
  тоггл «Решения»;
- после сжатия (`after-compact`) счёт сбрасывается: правила скилла из контекста
  ушли, скилл надо вызвать заново. Список прочитанных страниц остаётся: это
  не знание агента, а подсказка, где искать цель записи;
- чтение Craft (`post-tool` на `craft_read`) — id из команды встают в начало
  списка прочитанных страниц.

Скилл, который Влад вызвал сам командой `/craft-task`, через инструмент
`Skill` не идёт, и `post-tool` на нём не приходит. Замок его не видит и
запись в этом ходе запретит. Тогда агент вызывает скилл ещё раз
инструментом.

Хуки параллельных вызовов идут параллельно. Поэтому чтение и запись счёта
идут под локом на файл `craft-type-lock.lock` рядом с состоянием: иначе два
скилла в одном сообщении перезаписали бы друг друга.

В автономном прогоне поведение то же.

Зачем замок, а не правила в ответе хука: правила, которые хук кладёт в ход,
занимают контекст на каждой записи, даже на верной. Замок на верной записи
молчит и ходит по своему журналу, в сеть только за местом записи.

## Где файл состояния

Зона сессии хранилища, файл `craft-type-lock.json`:
`{"turn": 3, "skills": {"craft-task": 3}, "reads": ["‹id страницы›"], "place_warned": false}`. Каталог хранилища — из журнала
установки, у модуля без установщика `~/.local/state/jarvis/‹сессия›/`.
Испорченный файл, в том числе `reads` не из id блоков, — ошибка с путём к
файлу, а не тихий сброс. Каждое
следующее событие будет падать так же, пока файл на месте. Лечится
удалением `craft-type-lock.json` в зоне сессии: счёт начнётся заново, и до
нового вызова скилла запись с тегом будет под запретом.

## Как выключить

Режимом модуля из ядра: `{"craft-type-lock": false}` в одном из трёх
источников — `modes.json` в зоне сессии, личный `~/.config/jarvis/modules.json`
или `modules.json` рядом с папками модулей. Действует со следующего события.

## Часть lib для соседей

`lib/` отдаёт соседям по slug справочник «тег → скилл» и поиск тегов в
команде записи: так ревью хода `turn-review` узнаёт тип записанной сущности.
Код остаётся в `hooks/module.py`, а `lib/` только загружает его без запуска.
Поэтому правило «тег в тексте ссылки не считается» живёт в одном месте и
меняется сразу у всех.

## Зависимости

`requires` — пять модулей-скиллов: `craft-task`, `craft-stage`,
`craft-section`, `craft-note`, `craft-decision`. Без них запрещать бессмысленно: вызвать нечего.
Пока чего-то нет, библиотека молчит за замок и говорит в чат, чего не хватает.

Тесты: `python3 -m unittest tests.test_craft_type_lock`.
