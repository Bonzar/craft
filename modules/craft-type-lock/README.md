# craft-type-lock

Замок «запись в тип сущности без его скилла». Агент не запишет в Craft
сущность с тегом типа, пока в этом ходе не вызвал скилл этого типа.

## Что ловит

Вызов `craft_write` и `craft_write_and_show` сервера Craft MCP, в команде
которого есть тег типа. Второй инструмент исполняет те же команды, что и
первый, поэтому закрыт тоже. Инструмент узнаётся по хвосту имени
(`mcp__‹сервер›__craft_write`): имя сервера зависит от того, как Craft
подключён, и замок от него не зависит.

Тег ищется по всей строке команды: в `--markdown`, в JSON после `--json`, в
пачке через `;`. Тег с хвостом тоже тег: `#задача/готово`, `#этап/отменено`.
Слово, которое только начинается как тег (`#задачами`), тегом не считается.
Регистр не важен: `#Задача` — тот же тег. Кириллица, записанная в JSON как
`\uXXXX`, разворачивается перед поиском.

Текст ссылки на блок (`[Сборка #этап](block://…)`, то же с `craftdocs://`)
из поиска вырезается. Текст ссылки — копия имени цели с её тегами, поэтому
такие ссылки есть почти в каждой записи: у задачи проекта — ссылка на этап,
у этапа — ссылки на разделы. Ссылка цель не пишет, и скилл цели для неё не
нужен.

Какой тег какой скилл требует — `data/types.json`, поле `types`, у каждого
тега `skill`. Больше там ничего нет: id разделов и шаблонов типа живут в
`skill/SKILL.md` самих скиллов.

Нет вызова скилла этого типа в текущем ходе — запрет. В причине: какой тег
найден, какой скилл вызвать, и что после вызова запись надо повторить. Скилл
вызван — замок молчит.

## Что не ловит

- Решения. Тега у решения нет, по команде его не отличить от любого другого
  текста. Поэтому скилла `craft-decision` в `types.json` нет, и замок его не
  требует.
- Запись без тега типа: правку текста блока, таблицы, коллекции, покупки.
  Замок молчит и пишет в след «тега типа нет».
- Запись по id без текста тега: закрытие через `tasks update --id … --state
  done`, `blocks move` закрытой задачи или этапа, `blocks delete`, тело задачи
  отдельными блоками через `blocks add --id ЗАДАЧА`. Тега в команде нет —
  замок молчит, хотя правила закрытия и переноса живут в скиллах.
- Справку без тега: `tasks add --help`. Справку с тегом в команде замок
  проверяет как запись: `--help` в полезной нагрузке иначе открывал бы замок.
- Чтение: `craft_read` замок не трогает.
- Запись из Codex. Обёртка Codex пока знает только старт и сжатие, событий
  `pre-tool`, `post-tool` и `prompt` у неё нет. Установщик ставит замок и
  туда, но предупреждает: в Codex он не сработает.

## Как устроен ход

Ход — от реплики до реплики. Счёт хранит сам замок:

- реплика (`prompt`) — номер хода растёт на 1;
- вызов инструмента `Skill` (`post-tool`) со скиллом типа — скиллу пишется
  номер текущего хода. Имя скилла с префиксом плагина (`плагин:craft-task`)
  берётся по части после последнего двоеточия;
- запись в Craft (`pre-tool`) — каждый скилл найденных тегов должен нести
  номер текущего хода;
- после сжатия (`after-compact`) счёт сбрасывается: правила скилла из контекста
  ушли, скилл надо вызвать заново.

Скилл, который Влад вызвал сам командой `/craft-task`, через инструмент
`Skill` не идёт, и `post-tool` на нём не приходит. Замок его не видит и
запись в этом ходе запретит. Тогда агент вызывает скилл ещё раз
инструментом.

Хуки параллельных вызовов идут параллельно. Поэтому чтение и запись счёта
идут под локом на файл `craft-type-lock.lock` рядом с состоянием: иначе два
скилла в одном сообщении перезаписали бы друг друга.

В автономном прогоне поведение то же.

Зачем замок, а не правила в ответе хука: правила, которые хук кладёт в ход,
занимают контекст на каждой записи, даже на верной. Замок на верной записи
молчит и ходит только по своему журналу — в Craft и в сеть он не ходит.

## Где файл состояния

Зона сессии хранилища, файл `craft-type-lock.json`:
`{"turn": 3, "skills": {"craft-task": 3}}`. Каталог хранилища — из журнала
установки, у модуля без установщика `~/.local/state/jarvis/‹сессия›/`.
Испорченный файл — ошибка с путём к файлу, а не тихий сброс. Каждое
следующее событие будет падать так же, пока файл на месте. Лечится
удалением `craft-type-lock.json` в зоне сессии: счёт начнётся заново, и до
нового вызова скилла запись с тегом будет под запретом.

## Как выключить

Режимом модуля из ядра: `{"craft-type-lock": false}` в одном из трёх
источников — `modes.json` в зоне сессии, личный `~/.config/jarvis/modules.json`
или `modules.json` рядом с папками модулей. Действует со следующего события.

## Зависимости

`requires` — четыре модуля-скилла: `craft-task`, `craft-stage`,
`craft-section`, `craft-note`. Без них запрещать бессмысленно: вызвать нечего.
Пока чего-то нет, библиотека молчит за замок и говорит в чат, чего не хватает.

Тесты: `python3 -m unittest tests.test_craft_type_lock`.
