# review-craft-calls

Поставщик данных ревью хода для Craft. На `post-tool` пишет в объём ревью четыре вызова:

- `craft_write` и `craft_write_and_show` — запись `write` с командой как есть и ответом.
- `craft_read` — чтение `read` с id блоков.
- `Skill` — запись `skill` со slug скилла.

Инструмент Craft MCP узнаётся по хвосту имени (`mcp__‹сервер›__craft_write`). Прочие инструменты Craft в объём не идут: модуль молчит, в следе причина с именем инструмента. Вызов не Craft и не скилл — молчание со своей причиной. Вызовы подагента в объём не идут.

Модуль — поставщик по контракту из README `turn-review`, раздел «Контракт поставщиков»: шапка объявляет `for = ["turn-review"]`, строка объёма — словарь с `kind`, `prompt_id` реплики из сырого события и полями вида, дописывается `Storage.append_line` ядра в файл `turn-review-volume.jsonl` зоны сессии. `lib` ревью модуль не импортирует и ревью не требует. Своего описания записей у модуля нет: формат и смысл строк задаёт контракт ревью.

Тегов типа модуль не ищет и сущностей не знает: команда записи ложится как есть, её тип кладут в объём строкой `entity` модули сущностей и замок типов, не этот модуль. Команду Craft разбирает `lib` модуля `command-tree-craft`: имя инструмента, команда из входа, id блоков чтения.

Требует `command-tree-craft`. Ставится в любой харнес, где обёртка переводит `post-tool`.
