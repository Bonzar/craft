# review-craft-calls

Поставщик данных ревью хода для Craft. На `post-tool` пишет в объём ревью через `lib` модуля `turn-review` четыре вызова:

- `craft_write` и `craft_write_and_show` — запись `write` с командой, ответом и тегами типа.
- `craft_read` — чтение `read` с id блоков.
- `Skill` — запись `skill` со slug скилла.

Инструмент Craft MCP узнаётся по хвосту имени (`mcp__‹сервер›__craft_write`). Прочие инструменты Craft в объём не идут: модуль молчит, в следе причина с именем инструмента. Вызов не Craft и не скилл — молчание со своей причиной. Формат записей — `data/review-records.md`, он подшивается в поручение подагенту.

Запись ложится функцией `append_turn_record`, номер хода ставит она. Состояние ревью испорчено — запись всё равно ложится, без номера, а хук падает с ошибкой. Подробнее — в README `turn-review`, раздел «Номер хода».

Теги типа в команде записи ищет библиотека замка `craft-type-lock` по `data/entity.json` модулей сущностей: сам поставщик сущностей не знает. Вызовы подагента в объём не идут.

Справочник тегов не собрался: `entity.json` испорчен или тег стоит у двух модулей. Тогда запись `write` всё равно ложится, с `types: null` и полем `types_error` с текстом ошибки. Потом хук падает с той же ошибкой. Установщик ловит такой файл раньше, при установке.

Требует `turn-review` и `craft-type-lock`. Ставится в любой харнес, где обёртка переводит `post-tool`.
