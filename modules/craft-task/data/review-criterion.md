## Критерий «task»: задача записана правильно

Для каждой записи `write`, чей тип (раздел «Тип записей» поручения) включает #задача, по порядку объёма. Правила — скилл `{{HARNESS_SETTINGS}}/skills/craft-task/SKILL.md`, прочитай его целиком. Найди id записанного блока в `result` или `command` и прочитай его и его родителя: `blocks get ‹id› --depth -1`. Не смог прочитать — замечание «блок не читается».

Проверки по одной на правило, каждая даёт не больше одного замечания на запись, текст замечания начинается с её названия и двоеточия:

1. **место** — задача этапа или сферы, работа, которая меняет правило, — задача этапа, служебная задача проекта — задача сферы.
2. **шапка** — инлайн-чекбокс с тегом, первая ссылка на сущность, из которой выросла, дальше от общего к частному, ссылок на задачи в шапке нет.
3. **описание** — до восьми строк: что не так, чем мешает, что делаем, откуда начинать, без плана по шагам.
4. **чек-лист** — пункт глагол и предмет короткой строкой, без придаточных и двоеточий, шагов процедуры агента нет.
5. **закрытие** — галочки по слову Влада, тег /готово, ссылки на задачу зачёркнуты; отменённая — тег /отменено, причина в задаче, состояние canceled.

Не замечание: оценка и /ждет, их ставит Влад. Вкус, стиль сверх правил, то, что проверить нельзя ни по блоку, ни по объёму.
