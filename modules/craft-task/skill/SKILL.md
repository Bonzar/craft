# Задача

Правила типа — разделы Craft: «Задача #раздел» (`ef7d3d73-bc05-0fb7-8cf9-f573e4a616b7`), «Оформление задачи #раздел» (`5a6084a2-f3cc-954f-c75d-1d3307dcebe0`), «Ведение задач и этапов #раздел» (`59447630-83d6-82ea-5609-20e24b34d607`), «Закрытие задачи #раздел» (`fcb73b91-a4cf-2569-988a-c356048f7d09`), «Изменение плана #раздел» (`e5d3a82c-59b8-4b76-a723-10fca94af4db`), «Регулярная задача #раздел» (`cf098807-fe46-bea1-cf60-67c3fae919af`).

## Когда вызывать

Вызывай перед каждой записью с тегом #задача, с любым хвостом и для регулярной тоже. Повторно — после новой реплики Влада и после сжатия контекста. Проверка craft-type-lock отклонила запись — вызови скилл того типа, который она назвала, и повтори запись.

В той же записи стоит тег другого типа — вызови и его скилл: #раздел — craft-section, #этап и #веха — craft-stage, #заметка и #тема — craft-note. Ссылка вида [… #тег](block://…) скилла другого типа не требует.

## Что прочитать до записи

1. Файл `{{HARNESS_SETTINGS}}/skills/craft-call/craft-base.md` целиком.
2. Шаблон и шесть разделов из шапки, `--depth -1`. Шаблон: «2. Задача» `844E93D5-D127-431D-898E-0B8B3E5889E2`, регулярная — «7. Регулярная задача» `f81558ef-89af-8796-d518-4e2d9f1b4721`.
3. Место свежим чтением: проект `--depth 2`, у задачи сферы — её секция сферы. Правка — сама задача `--depth -1`.
4. Перед правкой, закрытием и переносом прочитай входящие ссылки на задачу и сверь ссылающиеся фразы.

Ниже — выжимка разделов. Разошлись с разделом — прав раздел, покажи расхождение Владу.

## Шаги записи

1. Место. Задача проекта — +1 под этапом, в порядке выполнения и по сроку относительно соседей. Задача сферы — «Активное» или «Беклог». Работа, которая меняет правило, — только задача этапа. Регулярная сферы — в «Регулярном» сферы, регулярное дело проекта — в проекте.
2. Инлайн-чекбокс «- [ ] Название #задача», textStyle body, тело детьми. Оценку /15м, /30м, /1ч, /2ч+ спроси у Влада {{ASK}}.
3. Шапка. Первая ссылка — откуда выросла задача: этап, иначе тема, заметка, раздел или проект, иначе сфера. Эта сущность достижима из «Базы знаний» сферы. Дальше ссылки от общего к частному, ссылок на задачи нет.
4. Открытый вопрос — задача этапа, где он всплыл, со ссылкой на задетый раздел. В «Задачах» раздела — ссылка на неё.
5. Несколько задач одного результата — события, покупки, поездки — ссылаются в шапке на его сущность. Её нет — спроси Влада {{ASK}}, какой сущностью её завести, и заведи по её скиллу. Общий справочник получает только ссылку на эту сущность.
6. «Описание» до чек-листа — две-шесть строк сверху вниз: что не так, чем мешает или что откроет, что делаем, откуда начинать. Назови в нём причину работы. «Откуда начинать» — адреса: файлы, id страниц, команды. Короткая задача — две строки, которые раскрывают название. Фразу о том, что задачу ещё предстоит расписать, не пиши. Задачей бывает и работа без видимого результата, например замер.
7. Строка «что делаем» — содержательное действие, из неё видно, куда ляжет результат. План по шагам в «Описание» не пиши: вся работа стоит в чек-листе.
8. Чек-лист — все подзадачи. Пункт — глагол и предмет короткой строкой, без придаточных и пояснений через двоеточие: «найти кроссы». Кусок со своим результатом — отдельная задача. Своих шагов не пиши ни задачами, ни пунктами.
9. Ссылки, цены, адреса, характеристики — в раздел или заметку. Решение, принятое в задаче, пиши через craft-decision в «Решения» этапа или задетого раздела. Задача ссылается на них.
10. «Заметки» — лог только своей задачи: зачем, как, что вышло. Дальнейшее — ссылкой в «Следующем шаге».
11. Срок — плановая дата работы или события. Дедлайн — только «надо успеть к…» с последствием. Дату не в том поле переставь. Дату, которую Влад назвал или которая стоит в связанной сущности, ставь без вопроса, обычным показом записи. Дату, которую вывел сам, не ставь: спроси у Влада {{ASK}}. Даты нет ни в словах Влада, ни в связанной сущности — оставь задачу без срока.
12. Связи. A не начать без B — у A в «Зависит от» B, у B в «Следующем шаге» A, одним проходом. Ссылка ведёт прямо на задачу, этап или веху, а не на их контейнер. Свой порядок связывай так же. /ждет ставит Влад. У задачи с /ждет заполнено «Зависит от», тега оценки нет. Работа из «Зависит от» сделана — сними /ждет.
13. Регулярная — по шаблону «7»: блок регулярной задачи — инлайн-чекбокс, повтор задай механикой Craft. Внутри блока текст практики пиши простым текстом без чекбокса, ниже блок «Зачем». Шапка — две ссылки: контейнер, где задача лежит (сфера или проект), и источник (алгоритм или тема). Порядок ссылок — как в шаблоне. Тогглов «Зависит от», «Следующий шаг», «Заметки» нет. Каждое выполнение — датированная запись в «Хронологии».
14. Практика больше не нужна — выключи повтор и перенеси регулярную в «Архив» сферы. «Хронология» остаётся как есть.
15. Название не меняй. От задачи отделили часть в другую задачу — переименуй эту задачу под оставшийся объём. Самостоятельный кусок сделан по словам Влада — закрой задачу по сделанному, остаток вынеси новыми задачами этапа.

## План по ходу работы

Работай только в задаче, взятой в работу. Всплывшее по дороге сразу запиши пунктом или задачей, текущую задачу не бросай: она бывает только закрыта или явно запаркована. Следующую выбирай по приоритету, времени и силам.

Куда ложится изменение:

- часть того же результата — пункт чек-листа
- работа со своим результатом — задача этапа, где её сделают
- «хорошо бы» без обязательности — беклог
- срочное — задача перед текущей, текущую явно запаркуй
- задевает несколько проектов сферы — задача в каждом
- доработка закрытой задачи — новая задача
- отказ от задачи, этапа или дубля — /отменено с причиной, без удаления

Новое решение пиши через craft-decision в этап, который его примет: текущий или другой открытый. Правки задетого раздела нет ни в одном открытом этапе — заведи новый этап через craft-stage. Задачи этапа сверь через craft-stage: лишние отмени, недостающие добавь. Новый факт о предмете раздела пиши в раздел сразу через craft-section. Результат принят как есть — это решение в «Решения» этапа, задачу закрой.

## Закрытие

1. Закрывай, когда по словам Влада сделан весь чек-лист и результат действует там, где им пользуются. Правка кода действует, когда PR влит в основную ветку: проверь по PR.
2. За каждой отметкой пункта и каждой закрытой задачей — слова Влада именно про них. Перед /готово каждый пункт отмечен или переформулирован под фактический результат.
3. Влад сказал, что чек-лист сделан, — закрой задачу без вопроса «закрыть ли». Пункты, которые Влад отметил руками, подтверди у него до закрытия.
4. «Всё готово», «с этим закончили» не закрывают: покажи открытые задачи и пункты и спроси по каждому.
5. Вывод из слов Влада пункт не закрывает: «отправили» — не «дошла», «забор покрасили» — не «покрашен в два слоя». Такой пункт спроси до отметки.
6. Пункт, чей подход заменён решением, отмени, не отмечай выполненным.
7. Галочка и «#задача/готово». Ссылки на задачу зачеркни везде. В каждом списке ссылок поставь зачёркнутую ссылку под ссылки на живые задачи. Задачу проекта перенеси в конец «Закрытых задач» этапа, задачу сферы — в «Архив». Последняя живая задача этапа закрыта — проверь этап через craft-stage.
8. В начале сессии по проекту найди отмеченные без /готово. До остальной работы спроси Влада по каждой: закрыта ли, какие пункты сделаны, что было по ходу. Пиши только подтверждённое.

## После записи

1. Перечитай задачу и родителя: уровень на месте.
2. Сверь входящие ссылки: этап, «Следующий шаг» блокера, «Задачи» задетого раздела.
3. Записанный материал мог закрыть другую задачу этой сущности — спроси Влада.
4. Покажи Владу результат ссылкой на изменённый блок.
