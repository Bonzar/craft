# Задача

Правила типа — разделы Craft: «Задача #раздел» (`ef7d3d73-bc05-0fb7-8cf9-f573e4a616b7`), «Оформление задачи #раздел» (`5a6084a2-f3cc-954f-c75d-1d3307dcebe0`), «Ведение задач и этапов #раздел» (`59447630-83d6-82ea-5609-20e24b34d607`), «Закрытие задачи #раздел» (`fcb73b91-a4cf-2569-988a-c356048f7d09`), «Изменение плана #раздел» (`e5d3a82c-59b8-4b76-a723-10fca94af4db`), «Регулярная задача #раздел» (`cf098807-fe46-bea1-cf60-67c3fae919af`).

## Когда вызывать

Вызывай перед каждой записью с тегом #задача, с любым хвостом и для регулярной тоже. Повторно — после новой реплики Влада и после сжатия контекста.

Проверка craft-type-lock отклонила запись — вызови скилл, который она назвала, и повтори запись.

## Что прочитать до записи

1. Файл `{{HARNESS_SETTINGS}}/skills/craft-call/craft-base.md` целиком.
2. Шаблон, `--depth -1`: «2. Задача» `844E93D5-D127-431D-898E-0B8B3E5889E2`, регулярная — «7. Регулярная задача» `f81558ef-89af-8796-d518-4e2d9f1b4721`.
3. Место свежим чтением: проект `--depth 2`, у задачи сферы — её секция сферы. Правка — сама задача `--depth -1`.
4. Вызови скилл craft-reconcile и сверь запись по нему: цель, входящие ссылки, круг сверки. Сверку закончи до показа Владу.

Раздел из шапки читай `--depth -1`, когда на него указывает шаг ниже или случай в скилле не описан. Все шесть перед каждой записью не читай.

Ниже — выжимка разделов. Разошлись с разделом — прав раздел, покажи расхождение Владу.

## Шаги записи

1. Место. Выбери контейнер: этап или сферу. Работа, которая меняет правило, — только задача этапа. Служебные задачи проекта — оформить, разбить на этапы, ревизия — задачи сферы со ссылкой на проект. Регулярная — сферы или проекта. Где именно в контейнере стоит задача, говорит скилл его типа.
2. Инлайн-чекбокс «- [ ] Название #задача», `textStyle body` независимо от наполнения, тело детьми. Ссылки шапки и секции тела — на `indentationLevel 0` внутри чекбокса. `Описание` обязательно и у короткой задачи. Оценку /15м, /30м, /1ч, /2ч+ спроси у Влада {{ASK}}.
3. Шапка. Первая ссылка — откуда выросла задача: этап, иначе тема, заметка, раздел или проект, иначе сфера. Эта сущность достижима из «Базы знаний» сферы. Дальше ссылки от общего к частному, ссылок на задачи нет.
4. Открытый вопрос — задача этапа, где он всплыл, со ссылкой на задетый раздел. В «Задачах» раздела — ссылка на неё.
5. Несколько задач одного результата — события, покупки, поездки — ссылаются в шапке на его сущность. Её нет — спроси Влада {{ASK}}, какой сущностью её завести, и заведи по её скиллу. Общий справочник получает только ссылку на эту сущность.
6. «Описание» до чек-листа — не больше восьми строк сверху вниз: что не так, чем мешает или что откроет, что делаем, откуда начинать. Назови в нём причину работы. «Откуда начинать» — адреса: файлы, id страниц, команды. Короткая задача — две строки, которые раскрывают название. Фразу о том, что задачу ещё предстоит расписать, не пиши. Задачей бывает и работа без видимого результата, например замер.
7. Строка «что делаем» — содержательное действие, из неё видно, куда ляжет результат. План по шагам в «Описание» не пиши: вся работа стоит в чек-листе.
8. Чек-лист — все подзадачи. Пункт — глагол и предмет короткой строкой, без придаточных и пояснений через двоеточие: «найти кроссы». Кусок со своим результатом — отдельная задача. Своих шагов не пиши ни задачами, ни пунктами.
9. Ссылки, цены, адреса, характеристики — в раздел или заметку. Решение, принятое в задаче, в задачу не пиши: оно идёт в «Решения» этапа, раздела, проекта или сферы по скиллу их типа. Задача ссылается на них.
10. «Заметки» — лог только своей задачи: зачем, как, что вышло. Дальнейшее — ссылкой в «Следующем шаге».
11. Срок — плановая дата работы или события, поле `taskInfo.scheduleDate`. Дедлайн — только «надо успеть к…» с последствием, поле `taskInfo.deadlineDate`. Поле выбирай по смыслу даты, дату не в том поле переставь. Дату, которую Влад назвал или которая стоит в связанной сущности, ставь без вопроса, обычным показом записи. Дату, которую вывел сам, не ставь: спроси у Влада {{ASK}}. Даты нет ни в словах Влада, ни в связанной сущности — оставь задачу без срока.
12. Связи «Зависит от» и «Следующий шаг» и тег /ждет веди по скиллу craft-links: вызови его, когда заводишь задачу, меняешь порядок работы или работа, которую ждут, сделана.
13. Регулярная — по шаблону «7»: блок регулярной задачи — инлайн-чекбокс, повтор задай механикой Craft. Внутри блока текст практики пиши простым текстом без чекбокса, ниже блок «Зачем». Шапка — две ссылки: контейнер, где задача лежит (сфера или проект), и источник (алгоритм или тема). Порядок ссылок — как в шаблоне. Тогглов «Зависит от», «Следующий шаг», «Заметки» нет. Каждое выполнение — датированная запись в «Хронологии».
14. Практика больше не нужна — выключи повтор. «Хронология» остаётся как есть. Куда регулярная уезжает, говорит скилл её контейнера: сферы или проекта.
15. Название не меняй. От задачи отделили часть в другую задачу — переименуй эту задачу под оставшийся объём. Самостоятельный кусок сделан по словам Влада — предложи закрыть задачу по сделанному, остаток вынеси новыми задачами этапа.

## Вызовы для задачи

- Создавай задачу через `blocks add --json` с `textStyle body` явно, в том числе при вложенном массиве `content`. При вложенном массиве `content` отсутствие `textStyle` задаёт явный стиль страницы. В update задачи `textStyle` всегда `body`, стиль `page` из чтения не копируй.
- Имя — полная формулировка действия, только название и теги. Для рабочей задачи окружение — в квадратных скобках, первое слово после скобок с заглавной: «- [ ] [env] Название #задача/оценка». Тикет — внутри тела.
- Напоминание по умолчанию не ставь. Проставилось само, например при задании повтора, — сними через `reminder.enabled: false` в json блока. Особенности этого поля — в `craft-tool.md`, часть «Чекбоксы и повторы».
- Статус проверяй по `taskInfo.state`. Команды закрытия, отмены и повтора, скрытый стиль страницы и изменение времени закрытия описаны в `craft-tool.md`, часть «Чекбоксы и повторы».

## Согласованность состояния

В начале каждой сессии по проекту запускай `{{JARVIS_MODULES}}/craft-sync/bin/craft-sync --task-tags ‹id проекта›`. Проверка проходит страницу со всеми подстраницами и отдаёт JSON: отмеченные без /готово, отменённые без /отменено и открытые с закрывающим тегом, у каждой путь по страницам. Пустой `mismatches` при ненулевом `scannedTasks` означает, что расхождений нет. Непрочитанный id стоит в `errors`. Отмеченные без /готово разбирай с Владом по пункту 9 части «Закрытие».

## План по ходу работы

Работай только в задаче, взятой в работу. Всплывшее по дороге сразу запиши пунктом или задачей, текущую задачу не бросай: она бывает только закрыта или явно запаркована. Следующую выбирай по приоритету, времени и силам.

Куда ложится изменение:

- часть того же результата — пункт чек-листа
- работа со своим результатом — задача этапа, где её сделают
- «хорошо бы» без обязательности — беклог
- срочное — задача перед текущей, текущую явно запаркуй
- задевает несколько проектов сферы — задача в каждом
- доработка закрытой задачи — новая задача
- отказ от задачи, этапа или дубля — /отменено с причиной, без удаления

Новое решение в задачу не пиши: его место в «Решениях» выбирает скилл той страницы, куда оно ляжет. Задачи задетого этапа сверь: лишние отмени, недостающие добавь. Новый факт о предмете раздела пиши в раздел сразу. Результат принят как есть — это решение в «Решения» этапа, задачу предложи закрыть.

## Закрытие

1. Сделан весь чек-лист и результат действует там, где им пользуются, — предложи Владу закрыть задачу. Правка кода действует, когда PR влит в основную ветку: проверь по PR.
2. Закрывай только после слова Влада о закрытии. Сделанный чек-лист без этого слова задачу не закрывает.
3. Каждый пункт отмечай по словам Влада именно про этот пункт. Пункты, которые Влад отметил руками, подтверди у него до закрытия. Перед /готово каждый пункт отмечен или переформулирован под фактический результат.
4. «Всё готово», «с этим закончили» не закрывают: покажи открытые задачи и пункты и спроси по каждому.
5. Вывод из слов Влада пункт не закрывает: «отправили» — не «дошла», «забор покрасили» — не «покрашен в два слоя». Такой пункт спроси до отметки.
6. Пункт, чей подход заменён решением, отмени, не отмечай выполненным.
7. Галочка и «#задача/готово». Ссылки на задачу зачеркни везде, ссылки на отменённую — так же. В каждом списке ссылок поставь зачёркнутую ссылку под ссылки на живые задачи. Куда закрытая задача переезжает, говорит скилл её этапа или сферы.
8. Отмена — «#задача/отменено» с причиной в задаче и состояние canceled, без удаления. Отменённая переезжает туда же, куда закрытая.
9. В начале сессии по проекту найди расхождения чекбоксов и тегов по части «Согласованность состояния» выше. До остальной работы спроси Влада по каждой отмеченной без /готово: закрыта ли, какие пункты сделаны, что было по ходу. Пиши только подтверждённое.

## После записи

1. Перечитай задачу и родителя: уровень на месте.
2. Проверь входящие ссылки: этап, «Следующий шаг» блокера, «Задачи» задетого раздела.
3. Записанный материал мог закрыть другую задачу этой сущности — спроси Влада.
