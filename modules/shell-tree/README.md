# shell-tree — разбор команды оболочки

Модуль библиотечный: событий у него нет, его зовут по slug из `requires`. Так
его называют замки оболочки — им нужно знать, что именно выполнит строка,
прежде чем она выполнится.

Что даёт часть `lib`:

- `parse(command, cwd)` — дерево строки: звенья в порядке выполнения (`;`,
  `&&`, `||`, конвейеры, фон), слова после снятия кавычек, перенаправления с
  целью и режимом, тело heredoc, подстановки команд вложенными деревьями,
  снятые обёртки запуска, строка `bash -c` разобранная отдельным деревом и
  рабочий каталог каждого звена с учётом `cd` и `pushd` в звеньях до него;
- `verdict(command, cwd)` — пишет ли строка (`writes`: `да`, `нет`,
  `неизвестно`), список целей записи с видом (`файл`, `каталог`, `git`, `сеть`,
  `процесс`) и причина текстом.

Незнакомая команда — это `неизвестно`, а не `нет`: «не доказано, что только
читает» и «доказано, что только читает» это разные ответы, и замок спрашивает
человека на первом.

Оба вызова бросают `ShellTreeError`, когда разбора не вышло: нет бинарника (в
тексте — где искали), вызов упал, ответ не JSON. Ответа «только читает» по
умолчанию нет: замок, получивший его молча, пропустил бы удаление каталога.

## Чем работает

Разбор делает бинарник `shell-tree` на Go — исходник в `shell-tree/` в корне
репозитория, рядом с `craft-sync`. Полное дерево команды даёт только
`mvdan.cc/sh/v3`; у стандартной библиотеки Python есть лишь токены `shlex`, и по
ним не видно ни перенаправлений, ни подстановок, ни строки внутри `bash -c`.

Бинарник ищется в том же порядке, что у `craft-snapshot`: переменная окружения
`SHELL_TREE_BIN`, затем `~/.local/bin/shell-tree`, затем `PATH`.

Предикат «только читает» лежит данными в `data/shell/read-only-rules.json` — в
бинарник они не вшиты. Путь к файлу задаёт ключ `--rules` (у `verdict(...)` —
именованный аргумент `rules`), без ключа берётся файл с тем же именем рядом с
бинарником.

## Сборка

Строки для setup-скрипта облачного окружения, рядом со строкой сборки
`craft-sync`:

```bash
(cd "$REPO/shell-tree" && CGO_ENABLED=0 go build -ldflags="-s -w" -o "$HOME/.local/bin/shell-tree" .)
cp "$REPO/data/shell/read-only-rules.json" "$HOME/.local/bin/read-only-rules.json"
```

Сборка идёт из каталога самого бинарника, потому что go-модуля в корне
репозитория нет: `go build ./shell-tree` из корня отвечает «cannot find main
module». Обе строки нужны в контейнере: бинарник там не предустановлен и
пересоздание контейнера не переживает, а без файла списков `verdict` отвечает
ошибкой, называющей путь, по которому он искал.

Тесты разбора — `go test ./...` в `shell-tree/`, тесты этой части —
`python3 -m unittest discover -s tests -t .` из корня репозитория.
