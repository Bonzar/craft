# shell-tree — разбор команды оболочки

Модуль библиотечный: событий у него нет, его зовут по slug из `requires`. Так
его называют замки оболочки — им нужно знать, что именно сделает строка, прежде
чем она выполнится.

Что даёт часть `lib`:

- `parse(command, cwd)` — ответ `bash-classify` как есть (классификация, риск,
  команды с правилами и аргументами, вложенные команды, перенаправления,
  `parse_warnings`) плюс наш ключ `cwd_walk`: рабочий каталог каждой команды и
  признак, можно ли этому каталогу верить;
- `verdict(command, cwd)` — `writes` (`да`, `нет`, `неизвестно`), `targets`
  (`path`, `kind`, `via`; виды — `файл`, `каталог`, `git`, `сеть`, `процесс`),
  `reason` словами самого bash-classify, `notes` — что сделала страховка, и
  `classification` с `risk` как есть.

Незнакомая команда — это `неизвестно`, а не `нет`. Оба вызова бросают
`ShellTreeError`, когда разбора не вышло: нет утилиты (в тексте — где искали),
вызов упал, ответ не JSON, в ответе нет классификации. Ответа «только читает» по
умолчанию нет: замок, получивший его молча, пропустил бы удаление каталога.

## Чем работает

Разбор делает [bash-classify](https://github.com/fprochazka/bash-classify)
(MIT, Filip Procházka): tree-sitter-bash плюс база правил на 150+ команд в YAML.
Версия 0.11.0, ей нужен Python 3.12+. Утилита ищется в том же порядке, что
craft-sync у craft-snapshot: переменная `BASH_CLASSIFY_BIN`, затем
`~/.local/bin/bash-classify`, затем `PATH`.

## Установка

Для setup-скрипта облачного окружения и для мака одинаково:

```bash
UV_HTTP_TIMEOUT=180 uv tool install bash-classify==0.11.0
```

Длинный таймаут не украшение: на 30 секундах по умолчанию загрузка
`tree-sitter` в контейнере обрывается (замер 18.09.2026). Версия пришпилена —
база правил решает, что считается чтением, и ехать ей с обновлением молча
нельзя. `uv` сам ставит нужный Python, если в системе его нет.

## Чего у bash-classify нет и что модуль делает поверх

**Рабочий каталог звена.** Утилита его не считает. Команды она отдаёт плоским
списком в порядке текста, и по нему модуль проводит `cd`, `pushd` и `popd` от
каталога вызова, превращая относительные пути в полные. Границ подоболочек,
конвейеров и фона в её JSON нет: `(cd /tmp) && rm b` и `cd /tmp && rm b`
неразличимы, поэтому, когда в строке есть и переход каталога, и такой знак,
каталог не проводится вовсе, а цели остаются относительными и помечены об этом
в `notes`. Лучше без каталога, чем с чужим.

Путь перенаправления читается от каталога вызова, а при переходе каталога в
строке — не читается: владельца перенаправления bash-classify не называет,
цель приписана первой команде строки (замер 18.09.2026 на
`cd /tmp && cat > inner.txt` и `cat a.txt | grep x > out.txt`).

**Два слепых пятна bash-classify 0.11.0.** Оба замерены на живом 18.09.2026 и
оба врут в опасную сторону — показывают запись чтением:

- перенаправление внутри строки `bash -c` теряется: `bash -c "cat > README.md"`
  отвечает READONLY без целей, хотя `cat > README.md` отдельно — LOCAL_EFFECTS с
  целью. Страховка: делегированную строку модуль отдаёт той же утилите отдельным
  вызовом и сводит ответы строжайшим;
- рядом с heredoc теряется перенаправление вывода: `cat <<EOF > f.txt` —
  READONLY, в `redirects` только `<<`. Страховки против этого нет, поэтому
  команда с heredoc не может получить ответ «нет»: её вердикт — «неизвестно».

Ни одна из двух страховок не добавляет записи, которой нет: первая — повторный
вызов той же утилиты, вторая — понижение «нет» до «неизвестно».

## Тесты

Из корня репозитория: `python3 -m unittest discover -s tests -t .`.

- `tests/test_shell_tree.py` — наша часть на заглушках утилиты;
- `tests/test_shell_tree_corpus.py` — 233 кейса `data/shell/write-targets-cases.json`
  живой утилитой; без утилиты пропускается целиком.
