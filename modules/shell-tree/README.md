# shell-tree — разбор команды оболочки

Модуль библиотечный плюс один хук на себя: событий для чужих у него нет, его
зовут по slug из `requires`. Так его называют замки оболочки — им нужно знать,
что именно сделает строка, прежде чем она выполнится.

Ставится вместе с модулем: бинарник разбора он собирает сам на старте сессии,
из своих исходников в свои `bin/`, — нужен только Go на PATH.

Что даёт часть `lib`:

- `parse(command, cwd)` — дерево строки: звенья в порядке выполнения (`;`,
  `&&`, `||`, конвейеры, фон), слова после снятия кавычек, перенаправления с
  целью и режимом, тело heredoc, подстановки команд вложенными деревьями,
  снятые обёртки запуска, строка `bash -c` разобранная отдельным деревом и
  рабочий каталог каждого звена с учётом `cd` и `pushd`;
- `verdict(command, cwd)` — `writes` (`да`, `нет`, `неизвестно`), `targets`
  (`path`, `kind`, `via`, `relative`; виды — `файл`, `каталог`, `git`, `сеть`,
  `процесс`) и `reason` текстом.

У обеих есть третий, необязательный аргумент `storage` — хранилище того, кто
зовёт. С ним вызов дождётся живой сборки, если она ещё идёт; без него не
собранный бинарник сразу даёт исключение.

Незнакомая команда — это `неизвестно`, а не `нет`. Нет бинарника, упал вызов,
ответ не JSON — `ShellTreeError` с причиной. Ответа «только читает» по умолчанию
нет: замок, получивший его молча, пропустил бы удаление каталога.

## Из чего состоит

```
src/     исходники разбора на Go (mvdan.cc/sh/v3) и их тесты
data/    данные предиката: база команд bash-classify, списки «только читает»,
         лицензии и происхождение — README там же
hooks/   сборка бинарника на старте сессии
lib/     parse и verdict
bin/     собранный бинарник и отпечаток исходников, из которых он собран
```

`bin/` в репозитории нет: его делает хук. На старте он считает отпечаток файлов
`src/` и сравнивает с записанным рядом с бинарником — сошлось, значит делать
нечего. Холодная сборка в контейнере облака занимает секунды, тёплый старт —
доли секунды. Пока сборка идёт, в зоне сессии лежит маркер с её pid: по нему
`lib` отличает «собирается, подожди» от «не собран и не соберётся». Секунд в
ожидании нет — есть живой процесс.

Go на PATH не оказалось — хук молчит, а причину пишет в журнал модуля в зоне
сессии (`shell-tree.jsonl`, там же замер времени сборки). Сессия от этого не
падает: об отсутствии инструмента скажет `lib` тому, кто её позовёт.

Предикат «только читает» собран из двух источников данных, и путь к обоим
бинарнику даёт `lib` ключами `--rules` и `--commands` — рядом с собой он данные
не ищет:

- `data/commands/` — вендоренная база команд
  [bash-classify](https://github.com/fprochazka/bash-classify) (MIT), по
  YAML-файлу на команду. За ней слово о командах, которые она знает: она судит
  подкоманду с оглядкой на аргументы (`git tag v1` пишет, `git tag -l` читает) и
  знает ключи, доказывающие запись (`sed -i`). Её классификация читается как наш
  ответ: `READONLY` — не пишет, `LOCAL_EFFECTS`, `EXTERNAL_EFFECTS`,
  `DANGEROUS` — пишет, `UNKNOWN` — неизвестно.
- `data/read-only-rules.json` — наши списки. Отвечают за команды, которых в базе
  нет (`bat`, `od`, `xxd`, `cksum`, `cmp`, `dd`, `rmdir`, `truncate` и другие),
  держат обёртки запуска, оболочки-обёртки и пустые приёмники вывода. Строже
  базы они ответ сделать могут, слабее — никогда.

## Тесты

Разбор — из каталога исходников: `cd modules/shell-tree/src && go test ./...`.
Там же корпус из 233 кейсов старого разбора (`data/write-targets-cases.json`).

Хук и `lib` — из корня репозитория: `python3 -m unittest discover -s tests -t .`.
