# Разбор инбокса

Правила процесса — «Разбор инбокса #раздел» (`1af7b100-0109-3bc3-340f-46fa4bee47ac`). Виды сущностей, их шаблоны и размещение — «Сущность базы #раздел» (`a6784801-9d92-875c-f146-50159368745b`) и разделы по ссылкам оттуда. Здесь только порядок работы и вызовы.

Механика вызовов Craft — `rules/craft-tool.md` модуля craft-call, он уже в контексте. Форма разговора — `rules/behavior.md` модуля behavior.

## До разбора

Прочитать раздел «Разбор инбокса #раздел» целиком: чем элемент становится, куда ложится и что спрашивать — решения там, а не здесь.

Прочитать «Хронологию» регулярки «Разобрать инбокс #задача/15м» (`e9bdfea2-5461-23eb-a194-ad8b0264ef5b`, сфера «Личное», секция «Регулярное»). Последняя датированная запись — дата, с которой идёт разбор записей дня.

Собрать сырьё двух источников:

- инбокс — задачи без даты, не отдельный документ: `tasks list --scope inbox`;
- записи дня — `blocks get --date ГГГГ-ММ-ДД` по каждому дню от даты из «Хронологии» по сегодняшний.

Секция «Дневник» и тоггл «В этот день» в записях дня разбором не читаются и не трогаются.

## Сортировочный проход

Разбор начинается сортировочным проходом по всем элементам, по порядку корзин: сначала отсев мусора (очевидно отработанное и пустое), затем справочное (факт без решения, место которого очевидно), остальное — требующее решения.

Корзина назначается по худшему факту элемента: смесь фактов — целиком в «требующее решения», пофактовая оценка пройдёт в конвейере. Сомнение в корзине — туда же.

Мусор и справочное показываются пачкой, одним показом со счётчиком — так решение Влада тратится на решения, а не на подтверждение очевидного.

Элементы старше месяца подсвечиваются отдельной строкой: кандидат в беклог или на удаление, решение по каждому за Владом.

## Конвейер

Корзина «требующее решения» идёт по правилу «Поэлементный конвейер» из `rules/behavior.md`: элемент дословно, решение и обоснование текстом, ответ Влада, действие в базе, следующий элемент. Мусор и справочное в конвейер не идут — они уже закрыты пачкой.

Порядок — от старых записей к новым. Уверенность влияет только на то, насколько уверенно предложить, но не отменяет согласия Влада.

Отчёт по закрытому элементу сразу переходит в предложение по следующему, без отдельного вопроса «продолжать?»: конвейер сам по себе непрерывен, пауза нужна, только когда предложить нечего или элементы закончились.

Связанные записи. Если записи инбокса связаны между собой или с чем-то в базе, сначала поиском проверить, есть ли уже подходящая целевая сущность: `search --include "‹название›"`. Дальше по решениям раздела: цель уже есть — прочитать её и внести данные в неё; цели нет, но записи явно об одном — новая сущность, и что именно объединяем, уточняется у Влада {{ASK}}, дальше название и разбор исходных записей по секциям шаблона; неоднозначно, есть ли цель и к чему это относится, — спросить {{ASK}}, а не выбирать молча.

## Размещение

Куда едет элемент, решают разделы: «Разбор инбокса #раздел», «Заведение и закрытие проекта #раздел» (`d45bef7d-c055-8553-8ed8-2601fd422be0`), «Задача #раздел» (`ef7d3d73-bc05-0fb7-8cf9-f573e4a616b7`), «Беклог #раздел» (`2e7b9e67-42a3-2728-2a6b-7f021d3ee947`).

Задача собирается по шаблону «2. Задача» — «Сущность по шаблону #раздел» (`f47bb522-56eb-2f57-bdcc-3443c6499d20`); регулярная задача — по шаблону «7. Регулярная задача», не по полному шаблону задачи.

Превращение элемента в задачу — повод спросить у Влада срок, если он не следует явно из материала. Срок не остаётся пустым по умолчанию просто потому, что элемент не назвал дату сам.

Перенос из инбокса: задача перемещается к соседней задаче нужного раздела, затем ей дописывается тег #задача с оценкой и, если нужно, срок; результат перечитывается. Механика перемещения и уровня — в `rules/craft-tool.md`.

## Пост-действие по элементу

До перехода к следующему: сущность размещена, связи синхронизированы (шапка-родитель, двусторонние ссылки), исходная запись удалена из инбокса или записи дня. Полузакрытых элементов конвейер не оставляет.

## После разбора

Дописать в «Хронологию» регулярки «Разобрать инбокс #задача/15м» датированную запись о разборе: с неё начнётся следующий.
