# Проект

Правила — разделы «Проект #раздел» (`e7f1d126-2785-5f64-b92b-6785e0346f6b`), «Заведение и закрытие проекта #раздел» (`d45bef7d-c055-8553-8ed8-2601fd422be0`). Решения проекта пиши по скиллу craft-decisions. Здесь только своё у проекта.

Общая механика вызовов — `craft-tool.md` модуля craft-call. Оформление проекта — в этом скилле, этапов и вех — в скилле их типа. Разговор — `behavior.md` модуля behavior.

## Когда вызывать

Вызывай скилл перед каждой записью в страницу проекта или с тегом #проект, с любым хвостом. Запись в цель, в «Решения проекта», в «Беклог» и любой блок прямо на странице проекта — тоже запись в проект. Закрытие этапа — тоже: оно меняет состояние проекта. Повторно — после моей новой реплики и после сжатия контекста.

Проверка craft-type-lock отклонила запись — вызови скилл, который она назвала, и повтори запись.

## Что прочитать до записи

1. Файл `{{HARNESS_SETTINGS}}/skills/craft-call/craft-base.md` целиком.
2. Шаблон «3. Проект»: `blocks get 0EE20542-CDB8-4960-BFF4-A6F4C8D64E9E --depth -1`.
3. Только теперь данные: проект `blocks get ПРОЕКТ --depth 2`. Для нового проекта — сферу точечно: «Базу знаний», «Беклог».
4. Разделы, которые запись задевает: на которые ссылается решение и которые лежат под целью проекта.
5. Решение — вызови скилл craft-decisions.
6. Вызови скилл craft-reconcile и сверь запись по нему: цель, входящие ссылки, круг сверки. Перед правкой цели, закрытием и заменой решения входящие ссылки нужны и на правленый блок. Сверку закончи до показа мне.

Раздел правил из шапки читай `blocks get ‹id› --depth -1`, когда на него указывает шаг ниже или случай в скилле не описан. Все подряд перед каждой записью не читай.

Ниже — выжимка разделов. Разошлась с разделом — прав раздел, расхождение покажи мне.

Этот скилл ведёт запись сущности проекта. Порядок актуализации проекта в диалоге — в отдельном скилле просмотра проекта.

## Шаги записи

**Проект ли это.** Работа с целью, которая делится на этапы, — проект. Не делится или разовая — задача сферы. Замысел, за который ещё не взялись, лежит страницей в «Беклоге» сферы. Документом в «Проектах» он становится, когда начата работа.

**Заведение.**
1. Проект — отдельный документ в папке «Проекты» по шаблону «3. Проект». В названии эмодзи сферы, тег #проект в конце.
2. На корневой блок проекта скопируй `styling` из свежего чтения документа сферы: фон, цвета, шрифт, разделители.
3. Ссылку на проект поставь в «Базу знаний» сферы, секция «Проекты».

**Цель.**
- В callout цель: состояние, по которому видно, что проект закончен, прошедшим временем, не длиннее двух строк. «Улучшить кухню» не цель, «на кухне снова можно готовить» — цель.
- В callout только цель. Чего проект сознательно не делает, запиши решением в «Решения проекта» с причиной, по скиллу craft-decisions.
- Цель проверяется на просмотре проекта, отдельного ритуала нет.

**Страница.**
- Порядок секций — как в шаблоне: цель, под ней разделы, темы и заметки проекта без заголовка, «Решения проекта», этапы и вехи, «Регулярные», «Беклог».
- Разделы, темы и заметки проекта лежат под целью вместе, без группирующего заголовка. Начатая тема и заметка проекта лежат здесь же.
- Разделы заводи на те стороны проекта, где есть требования или решения. Проект над ними по дереву.
- Регулярное дело проекта — в «Регулярных» проекта. Практика больше не нужна — выключи повтор и оставь задачу на месте, спроси меня, куда её унести.
- Текущий этап — самый верхний незакрытый, отдельной пометки не ставь. Закрытые этапы сворачиваются внутрь вехи.
- Отдельного плана не заводи: план — это сам проект с вехами, этапами и задачами.
- Страницу проекта по порогу из «Разделения сущности #раздел» не режь.

## Решения проекта

Что считать решением, место, блок и замену бери из скилла craft-decisions. Своё у проекта: задетые разделы назови ссылками прямо в тексте решения. Текст ссылки — точное название раздела с тегом из свежего чтения.

## Закрытие

1. Закрылся этап проекта — проверь, все ли этапы проекта закрыты или отменены. Все — сверь цель из callout и беклог и предложи мне закрыть проект. Без моего слова проект не закрывай.
2. Проект закрывается, когда цель из callout достигнута и беклог пуст. Конец этапов сам по себе проект не закрывает: регулярные задачи проекта живут до цели.
3. Закрытие — тег #проект/завершен в названии. Куда закрытый проект уезжает, говорит скилл сферы.
4. Проект заменён другим — закрой его как завершённый: строка «заменён проектом …» со ссылкой в callout, открытые задачи отменены, содержимое уезжает страницей в «Архив» сферы, документ остаётся указателем на неё.

## Проверить перед вызовом craft_write

- В callout только цель, состоянием, не длиннее двух строк. «Не делаем» — решением в «Решениях проекта», не в callout.
- Решение в «Решениях проекта» называет задетые разделы ссылками.
- Закрываемый проект: цель достигнута, беклог пуст.

## После записи

Перечитай проект `--depth 2`. Секции стоят по шаблону. После переезда в архив перечитай документ-указатель.
