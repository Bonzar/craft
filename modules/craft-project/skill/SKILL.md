# Проект

Правила — разделы «Проект #раздел» (`e7f1d126-2785-5f64-b92b-6785e0346f6b`), «Заведение и закрытие проекта #раздел» (`d45bef7d-c055-8553-8ed8-2601fd422be0`). Решения проекта — ещё «Запись решения #раздел» (`ec77ae34-d737-f54e-ee3c-62d84833494b`).

Механика вызовов — `craft-tool.md` модуля craft-call, часть «Проекты, этапы, вехи». Разговор — `behavior.md` модуля behavior.

## Когда вызывать

Вызывай скилл перед каждой записью в страницу проекта или с тегом #проект, с любым хвостом. Запись в цель, в «Решения проекта», в «Беклог» и любой блок прямо на странице проекта — тоже запись в проект. Повторно — после моей новой реплики и после сжатия контекста.

Проверка craft-type-lock отклонила запись — вызови скилл, который она назвала, и повтори запись.

## Что прочитать до записи

1. Файл `{{HARNESS_SETTINGS}}/skills/craft-call/craft-base.md` целиком.
2. Шаблон «3. Проект»: `blocks get 0EE20542-CDB8-4960-BFF4-A6F4C8D64E9E --depth -1`.
3. Только теперь данные: проект `blocks get ПРОЕКТ --depth 2`. Для нового проекта — сферу точечно: «Базу знаний», «Беклог».
4. Разделы, которые запись задевает: на которые ссылается решение и которые лежат под целью проекта.
5. Вызови скилл craft-reconcile и сверь запись по нему: цель, входящие ссылки, круг сверки. Перед правкой цели, закрытием и заменой решения входящие ссылки нужны и на правленый блок. Сверку закончи до показа мне.

Раздел правил из шапки читай `blocks get ‹id› --depth -1`, когда на него указывает шаг ниже или случай в скилле не описан. Все подряд перед каждой записью не читай.

Ниже — выжимка разделов. Разошлась с разделом — прав раздел, расхождение покажи мне.

## Шаги записи

**Проект ли это.** Работа с целью, которая делится на этапы, — проект. Не делится или разовая — задача сферы. Замысел, за который ещё не взялись, лежит страницей в «Беклоге» сферы. Документом в «Проектах» он становится, когда начата работа.

**Заведение.**
1. Проект — отдельный документ в папке «Проекты» по шаблону «3. Проект». В названии эмодзи сферы, тег #проект в конце.
2. Стиль корня скопируй с дока сферы, как велит `craft-tool.md`.
3. Ссылку на проект поставь в «Базу знаний» сферы, секция «Проекты».
4. Служебные задачи проекта — оформить, разбить на этапы, ревизия — ставь в сферу со ссылкой на проект, не внутрь проекта.

**Цель.**
- В callout только цель: состояние, по которому видно, что проект закончен, прошедшим временем, не длиннее двух строк. «Улучшить кухню» не цель, «на кухне снова можно готовить» — цель.
- «Не делаем» пиши решением в «Решения проекта» с причиной, а не второй строкой callout. Пиши его, только когда есть чему расползаться.
- Цель проверяется на просмотре проекта, отдельного ритуала нет.

**Страница.**
- Порядок секций — как в шаблоне: цель, под ней разделы, темы и заметки проекта без заголовка, «Решения проекта», этапы и вехи, «Регулярные», «Беклог».
- Разделы заводи на те стороны проекта, где есть требования или решения. В их «Связях» ссылку на проект не ставь: проект над ними по дереву.
- Текущий этап — самый верхний незакрытый, отдельной пометки не ставь. Закрытые этапы сворачиваются внутрь вехи.
- Отдельного плана не заводи: план — это сам проект с вехами, этапами и задачами.
- Страницу проекта по порогу из «Разделения сущности #раздел» не режь.

## Решения проекта

**Место.** Решение в «Решения проекта» идёт, только когда оно задевает несколько разделов без общего родителя или весь проект. Решение одного раздела — в его «Решения», решение ветки — в «Решения» родителя. Решение, не нужное без работы этапа, — в «Решения» этапа.

**Что писать.**
1. Решение — мой выбор, у которого был отвергнутый вариант и от которого что-то зависит дальше. Способ — не решение.
2. Пиши только то, что решил я. Не сказал — решения не было. Кандидатов не копи ни в якоре сессии, ни черновиком в базе.
3. Причину и отвергнутый вариант бери из моих слов. Не назвал — спроси в списке конца хода. Решение до ответа про отвергнутое пиши без зачёркнутого.
4. Причину старого решения, которой в базе нет, не додумывай: спроси меня, по одному вопросу на решение.

**Блок.**
1. Блок — сосед тоггла «Решения проекта» на +1 от него, не ребёнок. Ставь рядом с решениями о том же, а не в конец по дате. Таких нет — после последнего решения.
2. Задетые разделы назови ссылками прямо в тексте решения. Текст ссылки — точное название раздела с тегом из свежего чтения.
3. Причина одна, называй её всегда.
4. В блоке одно решение и не больше одного отвергнутого варианта. Пиши обычными предложениями, без полей и обязательных оборотов.
5. Есть отвергнутый вариант — причина стоит после него: `~вариант~: причина`. Отвергнутое пиши как вариант, а не как прежнее состояние. Нет — причину пиши обычным предложением.
6. Несколько отвергнутых — по блоку на каждый. Предмет назови, не пересказывай.
7. Дату ставь, только когда она часть смысла.
8. Условие пересмотра известно — пиши «пересмотрим, если» в том же абзаце.

**Правка и замена.** Выбор действует — устаревшее в блоке правь на месте. Выбор действовал и перестал — замени по шагам:
1. Запиши новое решение блоком сразу после старого, с причиной замены, без своего заголовка.
2. Зачеркни старый блок. После «Заменено:» поставь ссылку на блок нового решения из свежего чтения. Текст ссылки — краткое название нового решения.
3. Каждое решение, которое стояло на заменённом, сверь с новым по craft-reconcile.

## Закрытие

1. Проект закрывается, когда цель из callout достигнута и беклог пуст. Конец этапов сам по себе проект не закрывает: регулярные задачи проекта живут до цели.
2. Закрытие — тег #проект/завершен в названии.
3. Проект целиком уезжает в «Архив» сферы, как велит `craft-tool.md`, вместе с его разделами. Ссылку в «Базе знаний» сферы оставь.
4. Темы проекта принадлежат и сфере: перед переездом проверь, что каждая достижима из «Базы знаний» сферы.
5. Проект заменён другим — закрой его как завершённый: строка «заменён проектом …» со ссылкой в callout, открытые задачи отменены, содержимое уезжает страницей в «Архив» сферы, документ остаётся указателем на неё.

## Проверить перед вызовом craft_write

- В callout только цель, состоянием, не длиннее двух строк.
- Решение в «Решениях проекта» задевает несколько разделов без общего родителя или весь проект и называет их ссылками.
- У решения одна причина и не больше одного отвергнутого варианта.
- Закрываемый проект: цель достигнута, беклог пуст.

## После записи

Перечитай проект `--depth 2`. Секции стоят по шаблону, решение — сосед тоггла «Решения проекта» на +1 от него, рядом с решениями о том же, зачёркнутое и ссылка «Заменено» целы. После переезда в архив перечитай «Архив» сферы и документ-указатель.
