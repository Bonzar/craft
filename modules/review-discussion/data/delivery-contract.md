# Контракт доставки обсуждения

Общий модуль `review-discussion` владеет настройками, HTTPS-клиентом Site,
claim/ack, проверкой событий и журналом отправленных ID. Адаптеры находятся
только через `registry.adapters(module_dir, 'review-discussion')`. Для
выбранного харнеса нужен ровно один адаптер с совпадающим `harness`.
Передачи кода через `requires` между этими модулями нет.

Библиотека адаптера экспортирует `Adapter(env)`. Метод
`send(target: str, payload: str) -> str` отправляет текст в существующий чат
`target`, возвращает подтверждённый queue ID или бросает ошибку. Он не
создаёт, не возобновляет и не форкает чат. Ошибка не содержит комментарий,
credentials или stdout/stderr внешней программы. Другому харнесу нужен
собственный проверенный адаптер.

POST `/api/delivery/claim`: `{session,target,instance}` →
`{cursor,events,busy,leaseSeconds}`. `cursor` — строка целого неотрицательного
числа. `events` — не более 50 `comment.created`, упорядоченных по cursor;
пробелы глобальной последовательности допустимы. Событие:
`{eventId,cursor,name,timestamp,data:{session,review,thread,message_id,text,quote,quote_truncated,url}}`.
URL обязан вести к настроенным Site и session. Отметок Ок здесь нет.

Один instance владеет lease 30 секунд. Занятая lease запрещает отправку.
Первый claim инициализирует server cursor на текущем максимуме: прежние
обсуждённые комментарии не пересылаются. Consumer нужно зарегистрировать
до следующего комментария: написанное до первого claim считается историей.

Один claim → одно событие. Queue receipt сначала фиксируется через core
Storage с fsync (eventId → queue ID), затем POST `/api/delivery/ack`:
`{session,target,instance,cursor,eventId}` → `{cursor}`. При сбое ACK новый
queue не создаётся. Следующий claim продлевает lease. Сервер хранит cursor
по `(session,target)`, независимо от машины и instance.

Гарантия — at least once. Между принятием queue и локальной фиксацией receipt
остаётся аварийное окно; queue CLI генерирует новый client ID на каждый
вызов. Стабильный eventId остаётся в сообщении для распознавания повтора.
Текст сообщения содержит комментарий целиком, начало цитаты до 240 символов
и ссылку на обсуждение. Фрагмент цитаты обозначен явно. Полный стабильный
eventId, ID ревизии и ID ветки передаются адресом ссылки; JSON-пакет, cursor,
timestamp и ID ветки не выводятся отдельными полями. Текст комментария и
цитаты оформлен цитированными строками. Полный контекст при необходимости
читается из указанной ревизии в Site по событию, а не из локальной копии.
У снимка связь с комментарием задают `session` и `thread` из ссылки:
`review_image(session, thread)` читает изображение именно этой ветки.
ID ветки берётся из `thread`, а не восстанавливается из eventId или цитаты:
ответы имеют независимые ID сообщений, сохраняя ту же ветку и её снимок.

Lease не даёт exactly once при зависшем процессе или потере local journal.
Успешный queue подтверждает постановку, а не завершение ответа модели.
