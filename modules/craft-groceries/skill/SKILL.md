# Продукты

Правка внутри страницы «Продукты» идёт без отдельного подтверждения: это предодобренная зона. Неоднозначность разбирается переспросом по этому скиллу.

Механика вызовов Craft — `rules/craft-tool.md` модуля craft-call.

## Страница

ID зафиксирован: `395450FC-468E-4EF6-8267-BC158A4E2EBC`. Страницу НЕ искать через `folders list`, `documents list` или `search` — открывать СРАЗУ по этому ID. `search` применяется только ВНУТРИ страницы (`--document 395450FC-…`) для получения ID товара, не для поиска самой страницы.

## Основной путь

1. Прочитать всю страницу одним проходом: `blocks get 395450FC-… --depth -1 --format markdown`. Категории — подстраницы, всё подтягивается за раз, `--cursor` и пагинация не нужны. JSON всей страницы не читать.
2. Семантически сопоставить запрос с товаром из прочитанного markdown — точное каноническое название как в списке (нормализуй регистр и эмодзи; синонимы род↔вид: «курица» ↔ «Куриное филе»). Точное важнее частичного. Неоднозначно — спросить {{ASK}}. Нет близкого — раздел «Добавление нового».
3. По каждому товару один точный поиск: `search --include "точное название" --document 395450FC-…` → ID блока.
4. Сменить состояние: `tasks update --id ‹ID товара› --state todo|done|canceled` (несколько — через `;`, в каждой команде один `--id`).

## Состояния

- `todo` 🔲 надо купить ← «надо купить / закончился / нет X»
- `done` ☑️ есть ← «купил / купили / взяли / есть X»
- `canceled` ❎ не покупаем ← «убери совсем / не покупаем X» (зачёркивание рисуется само, тильду руками не ставить)

## Добавление нового

Только если в прочитанном markdown нет ничего семантически близкого (список уже прочитан, повторно не читать).

1. Ещё раз дедуп по всем категориям.
2. Подобрать категорию из имеющихся на странице — подстраницы-категории видны в уже прочитанной структуре, в скилле они не перечисляются. Неоднозначно — спросить {{ASK}}.
3. Взять ID подстраницы нужной категории — он есть в уже прочитанной структуре (подстраницы отдаются со своими id).
4. Добавить товар: блок-задача (`listStyle` task) в состоянии todo (или done, если куплено), прямым блоком в конец подстраницы своей категории, без тега типа. Как физически создать и разместить блок — в `rules/craft-tool.md`.

## Запреты

- `--id` — это ID товара из поиска, НИКОГДА ID страницы `395450FC…` (иначе запись уйдёт в заголовок и сломает страницу).
- Статус существующих товаров — только через `tasks update --state`. Товар не удаляем, кроме только что ошибочно добавленного дубля.
- Всю страницу в json не читать: прохода `--depth -1` в markdown хватает и для пометки, и для добавления — он отдаёт id подстраниц.
- Не трогать вложенные подстраницы внутри списка (виды чая, Варенье, Зубная паста, Подставка для банок) — это не товары.

## Модель (справочно)

Товары — блоки `listStyle=task`, `taskInfo.state` из набора todo / done / canceled, разложены по подстраницам-категориям (каждая категория — отдельная подстраница страницы «Продукты»). Markdown отдаёт текст строк без ID, поэтому ID берём отдельным точным `search`. `tasks update --state` меняет только состояние: ID, позиция и блок-ссылки сохраняются.
