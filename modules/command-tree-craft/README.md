# command-tree-craft — разбор команд Craft MCP

Модуль чисто библиотечный: событий у него нет, его зовут по slug из
`requires` через `runtime.library('command-tree-craft').load()`. Брат
разбора команд оболочки: тот отвечает, что сделает строка оболочки, этот —
что делает команда Craft MCP.

Разбор чистый: ни сети, ни файлов, ни типов сущностей. Какие теги искать,
решает тот, кто зовёт, и передаёт набор сам. Справочник «тег → скилл» по
`data/entity.json` модулей сущностей сюда не входит: это контракт замка
типов с модулями сущностей.

## Что разбирает

- Имя инструмента. Имя сервера Craft MCP зависит от подключения, поэтому
  инструмент узнаётся по хвосту имени: `mcp__‹сервер›__craft_write`.
  `craft_write_and_show` исполняет те же команды, что `craft_write`, и тоже
  считается записью.
- Пачку команд. Команды через `;` режутся вне кавычек, как это делает сам
  Craft: `;` внутри `--markdown` и `--json` команду не режет. Обратный слеш
  экранирует следующий символ.
- Теги. Тег целым словом, хвост через слеш тоже тег: `#задача/готово`.
  Слово, которое только начинается как тег (`#задачами`), тегом не считается.
  Регистр не важен. Кириллица в JSON как `\uXXXX` раскрывается перед поиском.
  Текст ссылки на блок (`[Сборка #этап](block://…)`, то же с `craftdocs://`)
  из поиска вырезается: это копия имени цели, ссылка цель не пишет.
- Id блоков в команде и страницы в ответе `craft_read`: теги
  `<page id="…">` в markdown, корневой id в JSON. Регистр id API различает,
  поэтому id отдаются как есть, а повторы снимаются без учёта регистра.
- Цели записи. Флаги `--id`, `--ids`, `--siblingId`, `--targetId`,
  `--targetSiblingId` в любом месте команды, через пробел или «=», кавычки
  сняты, список через запятую разобран. У каждой цели роль: сосед
  (`--siblingId`, `--targetSiblingId`), родитель (`--id` у `blocks add`,
  `--targetId` у `blocks move`) или сам блок. Значения, на id не похожие,
  отдаются отдельно. Ещё — `--position before` и то, из тех ли команда, у
  которых цель есть всегда (`blocks add/update/move/delete`, `tasks update`).

## API

Все имена — из корня пакета, `craft.find_tags(…)` и так далее.

| Имя | Что делает |
| --- | --- |
| `craft_tool(tool_name)` | хвост имени MCP-инструмента; не MCP — пустая строка |
| `is_craft_write(tool_name)` | `craft_write` или `craft_write_and_show` |
| `is_craft_read(tool_name)` | `craft_read` |
| `command_of(tool_input)` | строка `command` из входа инструмента, иначе пустая |
| `CRAFT_WRITE_TOOLS`, `CRAFT_READ_TOOL`, `CRAFT_TOOL_PREFIX` | имена инструментов |
| `split_commands(text)` | команды пачки через `;` вне кавычек |
| `find_tags(command, tags)` | теги набора в команде вне текста ссылок, в нижнем регистре, по алфавиту |
| `tag_pattern(tags)` | регулярное выражение тега для набора |
| `decode_escapes(text)`, `strip_links(text)` | шаги перед поиском тегов |
| `BLOCK_ID`, `is_block_id(text)` | id блока |
| `block_ids(text)` | id блоков текста без повторов в любом регистре |
| `unique_ids(ids)` | повторы в любом регистре сняты, порядок первого вхождения |
| `answer_page_ids(answer)` | страницы из ответа `craft_read` |
| `write_targets(command)` | `Targets`: цели `Anchor(flag, block_id, role)`, неразобранные значения, `before`, `targeted` |
| `target_ids(command)` | id целей из флагов и полей `"id"` JSON |
| `verb_of(command)`, `is_before(command)` | глагол команды, `--position before` |

`write_targets` и `find_tags` работают по одной команде. Пачку вызывающий
режет сам `split_commands`, если ему нужно судить команды по отдельности.

## Кто зовёт

- `craft-type-lock` — замок «запись в тип без его скилла»: инструмент, теги
  записи по своему справочнику, страницы чтения, цели записи для суждения о
  месте.
- `review-craft-calls` — поставщик ревью хода: инструмент, команда, id
  блоков чтения.
- `turn-review` — ревью хода: теги в командах записей объёма по тегам из
  правил `applies: tags` своих критериев.

```
lib/ids.py       id блоков и страницы ответа чтения
lib/targets.py   цели записи
```
