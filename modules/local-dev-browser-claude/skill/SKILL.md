# Локальный дев-сервер в браузере

## Почему не встроенный браузер

Встроенный браузер Claude Desktop не пускает запросы страницы к локальной
машине и частной сети: `localhost`, `127.0.0.0/8`, `10/8`, `172.16/12`,
`192.168/16`, а также имена, которые туда резолвятся. Переход на такую
страницу проходит, HTML грузится, а скрипты, `fetch` и прочие подзапросы
получают `net::ERR_BLOCKED_BY_CLIENT` и даже не попадают в сетевой лог.
Настройкой это не снимается. Признак — пустая страница при живом сервере,
который отвечает `curl` кодом 200.

Не тратить время на обходы: смену IP в `/etc/hosts` на адрес из частной сети,
запуск через превью-конфиг, туннель с переносом сессии. Частная сеть режется
так же, а перенос сессионных кук между доменами — это работа с учётными
данными пользователя, её не делаем.

## Рабочий путь: отдельный Chrome по CDP

1. Пользователь сам запускает отдельный экземпляр Chrome с портом отладки и
   отдельным профилем, чтобы не трогать основной:

   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9222 --remote-debugging-address=127.0.0.1 --user-data-dir="$HOME/.cache/claude-cdp-profile"
   ```

2. В этом окне пользователь сам открывает дев-сервер и логинится. Пароли и
   токены Claude не вводит и не переносит; вход — дело пользователя.
3. Claude подключается к `http://127.0.0.1:9222` и работает в той же вкладке.
   Этот Chrome не встроенный браузер Claude, поэтому локальные адреса в нём
   открываются как обычно.

Подключаться через Playwright MCP с `--cdp-endpoint http://127.0.0.1:9222`:
`browser_navigate`, `browser_click`, `browser_type`, `browser_snapshot`,
`browser_take_screenshot`, `browser_evaluate`, `browser_console_messages`,
`browser_network_requests`. Если его инструментов в сессии нет, попросить
пользователя подключить его и начать новую сессию — инструменты MCP
появляются только при её старте:

```bash
claude mcp add playwright -- npx @playwright/mcp@latest --cdp-endpoint http://127.0.0.1:9222
```

## Как проверять

- После каждого шага — снимок или скриншот страницы, плюс консоль и сеть за
  время действия: результат подтверждается ими, а не только картинкой.
- Сеть буферизуется на вкладке ограниченно: читать сразу после действия.
- Диалоги `alert`/`confirm` блокируют страницу; кнопки, которые их вызывают,
  нажимать только с предупреждением пользователя.

## Безопасность

- Порт отладки даёт полный контроль над этим Chrome любому локальному
  процессу: слушать только `127.0.0.1`, отдельный профиль, после работы
  попросить пользователя закрыть окно.
- Не читать и не выводить значения кук и токенов; не переносить сессию в
  другие браузеры, домены и туннели.
- Не ослаблять системные и корпоративные политики (MDM, политики браузера):
  если что-то упирается в политику, сказать пользователю, кто её владелец.
