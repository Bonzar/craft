# Старые гварды: что запрещали и почему

Материал для замка «антипаттерн». Здесь причины и кейсы гвардов снятого слоя
JS-хуков — не документация кода: самого кода в репозитории больше нет, и
переносить его никуда не планируется. Что ловил гвард, почему его завели и на
каких примерах это закреплено — чтобы замок не пришлось выводить заново.

Формат кейсов: «команда (или вход) → ожидаемый ответ». Ответы старого слоя:
**deny** — вызов блокировался, **allow** — проходил, **silent** — хук молчал.

---

## `universal-block-no-verify.js` — обход git-хуков репозитория

**Что запрещал.** Две формы обхода git-хуков у Bash-вызова:

1. подмену каталога хуков — `git -c core.hooksPath=…`;
2. пропуск проверок при коммите и отправке — `git commit`/`git push --no-verify`.

**Почему.** Хуки репо (pre-commit, pre-push) ловят ровно то, что сломает сборку:
падает хук — чини причину, а не выключай проверку. Обход действительно бывает
нужен (сломанный хук, осознанное решение), но это решение Влада, и проходит он
явным разрешением на конкретный вызов, а не молча.

**Как отличал.** Подмена каталога искалась по СЫРОЙ команде, потому что значение
бывает в кавычках, и без учёта регистра — имена git-конфига регистронезависимы.
Флаг пропуска проверок искался иначе: сперва вычёркивались кавычные строки
(сообщение коммита, упоминающее флаг, обходом не является), затем команда
резалась на сегменты, и отказ выносился только сегменту, где встретились и
`git`, и `commit`/`push`, и сам флаг. На всём неожиданном — fail open.

**Кейсы.**

| Команда | Ответ |
|---|---|
| `git commit --no-verify -m "wip"` | deny |
| `git push --no-verify origin main` | deny |
| `npm run build && git commit -a --no-verify` | deny — цепочка, флаг во втором звене |
| `git -c core.hooksPath=/dev/null commit -m "x"` | deny |
| `git -c "core.hooksPath=/tmp/empty" push` | deny — значение в кавычках |
| `git commit -m "fix: normal commit"` | allow |
| `git commit -m 'docs: never use --no-verify'` | allow — флаг внутри сообщения коммита |
| `grep -rn -- --no-verify docs/` | allow — флаг без git |
| `git push origin HEAD` | allow |
| `npm test` | allow — не-git команда |

## `universal-config-protection.js` — правка конфигов линтеров и форматтеров

**Что запрещал.** Правку СУЩЕСТВУЮЩИХ конфигов линтеров и форматтеров
инструментами записи (Write, Edit, MultiEdit). Покрытие шло по имени файла:
`.eslintrc`, `.eslintrc.*`, `eslint.config.*`, `.prettierrc`, `.prettierrc.*`,
`prettier.config.*`, `biome.json*`, `.stylelintrc`, `.stylelintrc.*`,
`stylelint.config.*`, `ruff.toml`, `.ruff.toml`, `.editorconfig`.

**Почему.** Агент, у которого не проходит проверка, склонен «чинить» конфиг
вместо кода. Падающая проверка указывает на код, правило под неё не подгоняется.

**Что НЕ гейтилось и почему.**

- Создание НОВОГО конфига (файла нет на диске) — это сетап проекта, а не
  ослабление проверок.
- Конфиг проекта на питоне (`pyproject.toml`) — НАМЕРЕННО: там метаданные
  проекта вперемешку с настройками линтера, и блок ломал бы законные правки
  зависимостей.
- Байпаса через окружение не было вовсе: файловые инструменты не несут команды,
  куда можно было бы вписать маркер, — обход только явным разрешением Влада на
  конкретный вызов. На всём неожиданном — fail open.

**Кейсы.**

| Вход | Ответ |
|---|---|
| `Edit` существующего `.eslintrc.json` | deny |
| `Write` поверх существующего `.eslintrc.json` | deny |
| `Write` нового `.prettierrc` (файла нет на диске) | allow |
| `Edit` обычного существующего файла | allow |
| `Edit` `pyproject.toml` | allow — намеренно не гейтится |

## `universal-kill-by-name-guard.js` — гашение процесса по имени и маске

**Что запрещал.** Гашение процесса, адресованное ИМЕНЕМ или маской, в любой из
трёх форм: `pkill`/`killall` сами по себе, `kill $(pgrep …)`/`$(pidof …)` через
подстановку поиска по имени, `pgrep … | xargs kill` через конвейер.

**Почему.** На машине, где экземпляр не один (браузер под несколькими сессиями,
демон, сервер), такое гашение бьёт по чужим. Инцидент, ради которого гвард
заведён: гашение по точному имени на общем маке снесло рабочие браузеры двух
чужих сессий вместе со своим замерочным. Текстовое правило про это существовало
и не удержало — отсюда машинная ступень. Точное имя от маски здесь ничем не
отличается: обе формы бьют по всем экземплярам разом, разница только в
уверенности прицела.

**Что предлагалось взамен.** Адресовать СВОЙ экземпляр: номер процесса из своего
pid-файла (`kill "$(cat mypid)"`) либо порт, на котором он слушает
(`lsof -ti tcp:PORT -sTCP:LISTEN`). Своего идентификатора нет — сначала завести
его, а не гасить по имени.

**Область.** Гвард видел текст вызова целиком, поэтому ловил и команды, уходящие
на другую машину через `ssh host '…'`. Регулярки построчные: многострочная
команда иначе читалась бы не так, как её выполнит оболочка.

**Кейсы.**

| Команда | Ответ |
|---|---|
| `pkill -f chrome` | deny — маска |
| `pkill -x "Google Chrome"` | deny — точное имя |
| `killall node` | deny |
| `kill -9 $(pgrep -f capgate)` | deny — имя через подстановку |
| `ssh agent@host 'pkill -x "Google Chrome"'` | deny — гашение на другой машине |
| `pkill -f chrome # быстро, не мелочись` | deny — давление срочностью запрет не отменяет |
| `kill -9 "$(cat /tmp/my.pid)"` | allow — по номеру процесса |
| `kill $(lsof -ti tcp:9333 -sTCP:LISTEN)` | allow — по своему порту |
| `git status --short` | allow — не про гашение |

## `universal-eval-materials-guard.js` — материалы замера во время замера

**Что запрещал.** Во время замера (переменная окружения `CRAFT_EVAL`) закрывал
от агента его собственные материалы: кейсы, раннер, грейдер и сохранённые
прогоны — `evals/cases`, `evals/lib`, `evals/runs`, `evals/run-*.sh`,
`evals/selftest.sh`. Проверялись все три поля, которыми приходит путь: у чтения
файла, у поиска по каталогу и самим шаблоном у обхода, — иначе обход тривиален.

**Почему.** В материалах лежат ожидаемые ответы, и чтение обесценивает
измерение. Задача решается по существу; правила, скиллы и остальной код читать
можно.

**Область.** Только внутри замера: в обычной сессии агент работает с эвалами как
с любым другим кодом. На всём неожиданном — fail open.

**Кейсы** (все, кроме последнего, — внутри замера).

| Вход | Ответ |
|---|---|
| `Read` `evals/cases/behavioral/incident-closure.jsonl` | deny — файл кейсов |
| `Read` `evals/lib/grade.sh` | deny — грейдер |
| `Read` `evals/runs/v3-honest-b/report.tsv` | deny — сохранённый прогон |
| `Read` `evals/run-incident-closure.sh` | deny — раннер |
| `Grep` по `evals/cases` | deny |
| `Glob` `evals/cases/**/*.jsonl` | deny |
| `Read` дока правил | allow |
| `Read` `SKILL.md` скилла | allow |
| `Read` файла хука | allow |
| `Read` `evals/README.md` | allow — README не материал |
| `Grep` по корню репозитория | allow |
| `Read` файла кейсов ВНЕ замера | allow — гвард молчит |

## `universal-check-console-log.js` — забытые отладочные логи

**Что делал.** Не блок, а ПРЕДУПРЕЖДЕНИЕ на Stop: искал `console.log` в
JS/TS-файлах, правленных за сессию, и печатал список «файл:строка» с просьбой
убрать или заменить логгером. Портирован из ECC (`check-console-log.js`).

**Почему.** Отладочные логи легко забываются в коде — хук напоминает убрать их
до коммита.

**Механика.** Из события Stop брался путь транскрипта, из JSONL транскрипта —
`file_path` всех вызовов Edit/Write/MultiEdit за сессию. Файлы фильтровались:
существующие `.ts`/`.tsx`/`.js`/`.jsx` вне зависимостей и тестов. Строки с
маркером `// keep-console` (осознанный лог) не считались. Ничего не нашёл или
нет транскрипта — тихий выход. На всём неожиданном — fail open.

**Кейсы.**

| Вход | Ответ |
|---|---|
| Stop, в транскрипте правлен `.ts` с `console.log` | предупреждение называет файл и НОМЕР СТРОКИ |
| та же строка, помеченная `// keep-console` | в отчёт не попадает |
| Stop, правлен только тестовый файл (`*.test.ts`) | silent — тесты гейт логов не смотрит |
| Stop без транскрипта | silent |

## Гвард ожидания человека (`tests/human-wait-unbounded.sh`)

**Что запрещал.** Любой срок у ожидания ЧЕЛОВЕКА. Это был не хук на вызове, а
проверка в CI: три места, где ожидание человека когда-то отваливалось по
таймеру, и в каждом закреплено то, что ТАМ ДОЛЖНО СТОЯТЬ.

**Почему.** Между зовом о помощи и действием человека стояло три независимых
часов, и ни одни не были выбраны осознанно — все три достались по умолчанию:
ожидание человека в слое ввода сдавалось через 15 минут; долгое ожидание в
пульте отвисало через 10 минут с исходом «ожидание истекло»; сам прогон убивался
по сроку в две минуты. Влад попросил, чтобы времени между зовом и его действием
не было ограничено.

Дефект глубже числа: машина не знает, когда человек освободится, а таймер
превращает «ещё не пришёл» в «отказал» — исход, не различающий два разных
события. Тот же корень, что у правила «Признак проверки обязан различать
исходы». Ожидание человека кончается тем, что он ответил, или тем, что вкладка
закрылась.

**Форма проверок.** Утвердительная: искалось то, что должно стоять. Искать
отсутствие числа бесполезно — «без срока» само выражается числом ноль, и запрет
на цифру ловил бы починку вместе с поломкой.

**Кейсы** (место → что должно там стоять).

| Место | Ожидаемый ответ |
|---|---|
| ожидание человека в слое ввода (`tools/mac/prelude.js`) | при отсутствии явного аргумента подставляется «без срока», а не число минут: `ms === undefined ? БЕЗ_СРОКА : ms` |
| долгое ожидание в пульте (`tools/mac/capgate.js`) | исхода «ожидание истекло» в КОДЕ нет — таймер, отдающий ответ сам по себе, это тот же срок; в комментарии фраза законна и объясняет, почему срока больше нет |
| срок прогона (`tools/mac/h.sh`) | срок по умолчанию не ограничен: `T="${2:-2147483}"`. Ноль инструмент прогона не принимает, а предельное значение рвёт прогон мгновенно — секунды переполняют таймер в миллисекундах; 2147483 секунды — наибольшее работающее, замерено |
