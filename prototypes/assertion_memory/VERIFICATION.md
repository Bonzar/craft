# Проверка памяти утверждений

Проверки выполняются на изолированных временных базах и синтетических сообщениях. Не используйте личную базу или журнал как тестовую фикстуру. Сохранённые логи в `tests/evidence` фиксируют результаты отдельных исторических прогонов; они не подтверждают, что текущая версия прошла полный набор.

## Локальные проверки без модели

Из корня репозитория в окружении с установленными `requirements-mcp.txt`:

```sh
python -m unittest prototypes.assertion_memory.tests.test_thought_store \
  tests.test_thought_service tests.test_thought_provider_contract
python -m unittest prototypes.assertion_memory.native_intake_test \
  prototypes.assertion_memory.desktop_fast_test \
  prototypes.assertion_memory.tests.test_manual_release
```

Файлы `test_*.py` внутри пакета содержат дополнительные сценарии поиска, очередей, версий, происхождения, восстановления и сохранности. Файлы `*_test.py` проверяют адаптеры отдельно. HTTP-тестам нужны зависимости MCP. Необязательное сравнение `tests/compare_graphiti.py` требует отдельной установки `graphiti-core[kuzu]==0.31.2`; оно не является зависимостью сервиса.

## Приёмка с подключённой моделью

Локальные тесты с подставной моделью не доказывают правильность ответов реального провайдера. Отдельно проверьте обычный ответ, неизвестное сведение, условное исключение, предложение без принятия, противоречие и исторический срез. Для каждого результата проверьте сохранённые источники, условия, авторство, обязательные продолжения и актуальность. Ошибка модели или исчерпание попыток проверки остаются незавершённым результатом.

Проверяйте построение нового ответа и повторное чтение сохранённой версии отдельно. Сверяйте `thought_repairs` и диагностику конкретной ошибки; отсутствие исключения в клиенте не доказывает завершение фоновой работы. Построитель ещё может нарушать контракт одного черновика ответа. Успешный отдельный сценарий не подтверждает готовность всей системы или масштабируемость.

## Межсессионный захват

Для живой приёмки отправьте в первой обычной сессии разрешённого тестового проекта однозначное решение с уникальной контрольной фразой. Во второй обычной сессии спросите о том же другими словами, без контрольной фразы. Сверьте ответ, ID извлечённого утверждения и запись `recalled` до ответа. Источник должен вести к первой сессии. Повторите с исключением и поздним предложением. Ввод через делегацию или искусственный payload не засчитывается.

Проверка сохранённых журналов двух сессий:

```sh
python3 -m prototypes.assertion_memory.native_acceptance --config "$MEMORY_CONFIG" \
  --source-session SOURCE_ID --reader-session READER_ID --marker UNIQUE_MARKER
```

Проверка сопоставляет исходную цитату с авторизованной пользовательской репликой, подтверждает захват до первого ответа и требует, чтобы журнал чтения второй сессии содержал её ID до первой реплики агента. В самой второй реплике контрольной фразы быть не должно. Тест проверяющего инструмента отвергает чтение, записанное между первой репликой агента и завершением хода.
