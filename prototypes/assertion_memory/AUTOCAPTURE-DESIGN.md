# Захват новых сообщений: локальный и облачный контуры

Статус: проектирование, 22 ноября 2026. Ни одна новая интеграция не включена. Область: только тексты новых, видимых владельцу сообщений его собственных бесед, которые он явно выбрал; не импорт истории и не журнал всего, что прочитал агент.

## Что работает где

| Поверхность | Способ | Насколько автоматически |
|---|---|---|
| Codex локально на Mac | Существующий нативный локальный сборщик. Хук регистрирует разрешённую сессию, отдельный процесс отслеживает новые сообщения и отправляет очередь в MCP. Можно проверить альтернативу на документированных `UserPromptSubmit` и `Stop`, не читая файлы истории. | Да, когда локальный исполнитель активен, доверие к хукам подтверждено и сессия включена. Пропуски должны быть видны. |
| Work, когда и оркестрация, и исполнение локальны | Документированные локальные хуки. Совместимость именно нашего адаптера с Work не доказана; отдельная синтетическая проверка обязательна. | Потенциально автоматический, пока доступен локальный хост. |
| Дымок / Dot, личный аккаунт | Подключённый приватный MCP-плагин: владелец просит сохранить конкретное сообщение/факт или явно включает режим сохранения на эту беседу; агент делает вызов и проверяет квитанцию. | Не хук. Даже сохранённая инструкция не гарантирует каждый ход, доставку сообщения и доступ к тому же плагину. Приватные сообщения подагентов не входят в поток. |
| Work Cloud, личный аккаунт | Установленный плагин для явного/добровольного сохранения через MCP. Подключённый Mac как исполнитель сам по себе не переносит локальные хуки на облачный координатор. | Нет документированной гарантии автоматической записи ходов через пользовательские хуки. |
| Дымок и Work Cloud с локальным доступом в управляемом workspace | Только глобальные администраторские `mcp_tool`-хуки при включённой политике и удалённых хуках в Agent Security. Локальные/командные/плагинные хуки и облачный `SessionEnd` не поддерживаются. | Условно. Сначала подтвердить доступность, точные события и поля у собственных синтетических тестов. Это не полный поток/audit trail; отсутствие поля видимости или устойчивого ID исключает автоматический захват. |
| Обычный ChatGPT | В беседе с доступным MCP инструментом пользователь явно сохраняет выбранный текст. Официальный экспорт данных подходит для отдельного ручного импорта после отбора, не для подписки на новые ходы. | Не обнаружен публичный потребительский хук новых ходов или публичный API для произвольной истории аккаунта. Не скрейпить UI/закрытый API и не переиспользовать cookies. |
| Codex Cloud (Work in → Cloud, включая iPhone) | Опубликованное окружение распространяет репозиторий, setup и разрешённые сетевые настройки, не означает доступ к репликам облачного координатора. Явный MCP-вызов возможен только если инструмент реально доступен в конкретном клиенте/задаче. | Перенос локального хука в контейнер не доказан и не заявляется. Для собственной программной обёртки можно отбирать документированные события только её собственных сессий; это не захват существующих задач ChatGPT/Codex Cloud. |
| Нативные подагенты | Не подписывать на приватный обмен. Пропускать только ту часть результата, которую родитель реально отправил владельцу как видимое сообщение; сохранять один раз по ID внешнего сообщения. | Документированные `SubagentStart/Stop` в Codex не дают разрешения на скрытый текст. Для подагентов Dot отдельный публичный пользовательский callback не подтверждён. |

Различие для реализации: «ручное сохранение» означает подтверждённый MCP-вызов для выбранного текста. «Помощник сам вызывает инструмент» означает негарантированную автоматизацию, а не событие платформы. «Автозахват» обещаем только после подтверждения полноты заданного потока и наблюдаемых отказов в его конкретном клиенте.

## Что переиспользуем из базы

- `modules/assertion-memory/lib/__init__.py`: регистрирует только подходящие локальные сессии Codex; подагента не регистрирует. `lib/native_capture.py`, `lib/outbox.py`, `lib/capture_worker.py`, `lib/frontier.py` уже отделяют авторизацию источника, курсор, локальную очередь и доставку. `modules/assertion-memory/mcp/connection.json` (объявление подключения) и `prototypes/assertion_memory/mcp_server.py` не нужно заменять новой базой.
- `prototypes/assertion_memory/NATIVE-INTAKE-EVIDENCE.md`: отдельно описан тестированный на синтетике watcher явных источников и отказ при неизвестном происхождении, ротации/замене, слишком большом промежутке; не обещана сплошная запись.
- `memory_capture_message`: существующий контракт устойчивых ID, автора, роли, видимой реплики и происхождения. Не давать клиенту бесконтрольно подменять provenance; адаптер выдаёт доказанное поле либо маркирует `manual`. Данные кладутся в SQLite до запуска worker; отключённая модель не блокирует хранение сырья.
- `UserPromptSubmit` и `Stop` подходят первому эксперименту без файлов: изучить фактический `prompt`, `turn_id`, `last_assistant_message`. Последнее поле может быть пустым и по определению не гарантирует все видимые промежуточные реплики. Проверить повтор Stop, синтетическую реплику при продолжении хука, отмену и отсутствие роли/ID; при сомнении не записывать, отметить пробел. Не открывать `transcript_path`/rollouts как запасной путь. Если нужна гарантированная полнота в собственном клиенте, захватывать только тот текст, который он действительно принял/показал, в его официальном протоколе.

## Предлагаемый конвейер

1. **Разрешение.** По умолчанию выключен. Разрешение привязано к конкретному владельцу, источнику, типу видимости и беседе/рабочему проекту; UI показывает состояние, срок и выключатель. Первое включение задаёт watermark «со следующего сообщения», не выгружает старую историю. Для облачной версии сначала только личная беседа с Дымком и отдельные синтетические идентификаторы; групповые/общие чаты, другие пользователи, Temporary Chat, чужие аккаунты и истории не входят. Новый канал или проект включаются отдельно. Потеря авторизации, смена идентичности, разрыв курсора или неизвестное поле видимости блокируют доставку.
2. **Точка доверия.** Адаптер получает только видимый владельцу окончательный текст роли `user` / `assistant`, стабильные `source_principal`, `conversation_id`, `message_id`, время/порядок и минимальное происхождение. Для Dot успешный инструмент отправки, если когда-либо доступен поддерживаемый event/callback, является отправной точкой для ответа; приватный root/child текст, роль reasoning/analysis, tool args/results, credentials, вложения и цитаты из чужих источников не добавляются. Отсутствие поддерживаемого события заменяется явным сохранением, не перехватом транспорта. Для явно вручную пересказанного вывода не выставлять авторство исходного собеседника.
3. **Проверка перед любым сохранением.** Положительный список ролей и типов; подтверждение авторства/владения; ограничение размера; средства обнаружения секретов, отказ и понятная причина без отправки исходного тела в телеметрию. Не считать детектор секретов гарантией: для чувствительных текстов режим по умолчанию отключён. Никаких запросов подтверждения на основе того, что написано в самом захватываемом тексте.
4. **Durable outbox.** Сначала транзакция: `event_id = SHA-256(version, source, verified_owner, conversation_id, message_id, role)` от канонической кодировки, отдельно хэш канонического тела; сохраняется запись `pending`. Та же система/ID/хэш возвращает исходную квитанцию; другой хэш на тот же ID создаёт конфликт для ручного разрешения. Редактирование и удаление трактуются как отдельные типы событий только с подтверждённым ID/ревизией и авторитетом источника; иначе карантин, не молчаливая замена. Разные устройства не должны переписывать один локальный курсор. Нужны монотонная граница ack и явный статус `gap`, а не потеря непрочитанной записи.
5. **Доставка.** HTTPS с проверкой сертификата и отдельной ограниченной авторизацией только на capture; секрет в защищённом хранилище, не в аргументах MCP/Prompt, репозитории или логах. Повторы с экспоненциальным backoff и jitter для 429/5xx/timeout; 401/403/конфликт блокируют и требуют проверки. Успех только после durable ack сервера; повтор после обрыва на любой стороне безопасен. Модель в другой очереди, сбой модели не откатывает сырьё. Отдельные статусы `pending capture`, `captured`, `waiting_model`, `gap`; не обещать «сохранено» при одном лишь локальном ack.
6. **Контроль.** Утверждённый срок хранения для ожидающих/сырых данных, выключение доступа, возможность удалить собственные импортированные сообщения и связанные производные по проверенному идентификатору; экспорт/удаление не обещает изменения истории исходной платформы. Никаких полных transcript dumps, сетевого перехвата, неофициального API, cookies или поиска приватных файлов и логов. Для импорта официального экспорта — отдельное разрешение и локальный просмотр/положительный список выбранных ветвей перед пересылкой чего-либо.

## Наблюдаемые проверки перед включением

1. **MVP в облаке:** приватной учётной записью отправить «сохрани пробную реплику» с уникальным синтетическим маркером в выбранной беседе; получить серверный receipt и затем найти ровно одну запись. Повторить одинаковый ID и текст; вернуть тот же receipt. Обычный оборот без запроса сохранения не должен создать запись. Повторить после перезапуска, при недоступном MCP и после смены разрешённой беседы. Проверить отсутствие побочных записей в других потоках.
2. **Локальная бета:** синтетические пользовательский и видимый ассистентский ходы появляются сразу после фиксации. Сопоставить экран результата с сохранёнными ролями и порядком; проверить повтор Stop, отсутствие последнего текста, interruption, несколько видимых сообщений, worker PID после сохранения, перезапуск и Mac offline. Если локальный Mac не участвует в тесте, не объявлять его установленным/проверенным.
3. **Отказоустойчивость:** сбросить сеть до отправки и после коммита, но до ack; схема должна показать очередь, а затем одну строку в базе. Для 20 последовательных сообщений получить 20 квитанций без сортировки по часам разных устройств. Курсор за пределами известных данных переводит поток в `gap`, без сканирования старой истории.
4. **Изоляция:** ни групповой участник, ни подагент, ни инструмент, ни секретоподобная строка, ни кусок reasoning/прикреплённый файл не становятся записью (даже если смешаны с синтетической обычной репликой). Передача поддельной роли/ID/идентичности отклоняется. Обрыв/отзыв доступа не включает fallback другой учётки.
5. **Управляемый workspace, отдельный эксперимент:** администратор разрешает узко заданный поток, проверяет фактический payload и соответствие событиям. Сверить журнал за 20 синтетических ходов с ожидаемыми событиями + 2 отрицательными сценариями таймаута и потерянного callback. Без стабильных ID, проверенного автора и видимости выпускать только ручной режим.
6. **Критерий готовности:** объявлять результат отдельно по поверхности и профилю («доступно», «проверено на синтетике», «нет/не подтверждены хуки»). Не распространять тест local-only на Dot или Codex Cloud. Реальные данные включать только после успешной проверки и подтверждения области.
