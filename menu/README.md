# menu/ — пересчёт недели меню

Читает коллекции Craft, прогоняет правила из алгоритма «Собрать меню на неделю»
и пишет находки в поле `problem` каждой записи. Что и в какой день — решает
человек; код только проверяет и никогда не переставляет блюда сам.

Зависимость одна — `node`. Сети требуется ровно столько, сколько нужно
connect-API: базовый URL с токеном берётся из `CRAFT_API_BASE` и в вывод не
печатается.

## Запуск

    node menu/recheck.mjs --discover            # какие коллекции есть и их id
    node menu/recheck.mjs --cooks <id> --meals <id> --purchases <id> \
                          --recipes <id> --products <id> --eaters <id>
    node menu/recheck.mjs --from 2026-09-08/обед    # не трогать прошлое
    node menu/recheck.mjs --dry-run                 # отчёт без записи

Шесть id можно не набирать каждый раз — положить их в `CRAFT_MENU_COLLECTIONS`
одним JSON-объектом с теми же ключами; флаги его перекрывают.

    export CRAFT_MENU_COLLECTIONS='{"cooks":"…","meals":"…","purchases":"…",
                                    "recipes":"…","products":"…","eaters":"…"}'

Код возврата: 0 — всё сходится, 1 — есть находки, 2 — не смог отработать.

`--from <дата>[/<слот>]` задаёт точку пересчёта: записи раньше неё не
трогаются, их `problem` остаётся как был. Без слота день берётся целиком.
Готовка без даты проверяется всегда — её нечем отсечь.

## Что проверяется

По готовкам:

- расход не больше выхода, а после факта остатка — не больше остатка;
- готовое живёт `keepDays` дней от даты готовки (для холодильника);
- готовка стоит в слот, где повар дома — по его же строке приёма;
- готовку кто-то ест, если она не уехала в морозилку запасом;
- у готовки есть дата.

По приёмам:

- приём дома или с собой чем-то закрыт;
- на ужин есть салат — он ищется среди дополнений по типу рецепта;
- обед и ужин одного дня у одного едока — разные блюда, и гарнир тоже;
- одно блюдо не дольше двух дней подряд;
- с собой едет только то, что лежит в холодильнике, а не в морозилке;
- продукт из состава рецепта годен на день приёма.

По закупкам:

- единица закупки — та же, что у продукта, иначе «нужно минус есть» не сложить;
- заход не позже первой готовки, под которую взят;
- закупка привязана хоть к одной готовке, если не отменена.

Отменённый приём расхода не создаёт и в проверках повторов не участвует.

## Устройство

- `lib/craft-api.mjs` — connect-API: список коллекций, чтение и запись записей.
- `lib/model.mjs` — сырые ответы в плоскую модель недели.
- `lib/rules.mjs` — сами правила. Чистые функции: модель на входе, находки на
  выходе, ни сети, ни записи. Отсюда же берутся тесты.
- `recheck.mjs` — CLI: собрать модель, прогнать правила, записать `problem`.

Тесты — `tests/unit/menu-rules.test.mjs`, запуск `node --test`.

## Чего код не делает

Не решает, что готовить, не переставляет приёмы и не правит раскладку на
странице недели. Находка — это повод к разговору, а не команда.

Ещё он не читает состав блюда из карточки: состав живёт связью
«Рецепты → Продукты», и пока она у рецепта пустая, проверка срока продуктов по
нему молча не сработает.
