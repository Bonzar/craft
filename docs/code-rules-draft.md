# Правила кода

> ЧЕРНОВИК для переноса в Craft (фаза 6). Канон будет жить в Craft; этот файл — staging, после записи удалить.

Правила для агента в код-сессиях: TypeScript + React (монорепо Яндекса и личные GH-проекты). Каждое правило меняет поведение — это не учебник.

## Стиль кода

Легаси-стиль окружения важнее личных предпочтений: в монорепо действуют его конвенции, и при конфликте с этими правилами побеждает окружение. Перед правкой смотри, как написан соседний код, и пиши в его стиле.

Простейшее решение, которое реально работает. Абстракции и обобщения впрок не строятся — только когда повторение уже случилось.

Данные не мутируются: правка объекта или массива возвращает новую копию (spread, `toSorted`), а не меняет вход.

Файл — до 800 строк (норма 200–400), функция — до 50, вложенность — до 4 уровней. Упёрся — режь: early return вместо вложенных условий, утилиты из разросшегося модуля.

Ошибки не глотаются молча: обработка на каждом уровне, пользователю — понятное сообщение, в лог — контекст. Пороговые числа и задержки — именованными константами, не магией в коде.

Внешние данные (ввод пользователя, ответ API, файл) не считаются валидными: проверка схемой на границе системы, fail fast.

## TypeScript

Экспортируемые функции и публичные API типизируются явно (параметры и возврат); локальным переменным хватает инференса.

`interface` — для объектных форм, которые расширяют или реализуют; `type` — для юнионов, пересечений, mapped-типов и пропсов компонента. Вместо `enum` — юнион строковых литералов.

Взаимоисключающие состояния — дискриминированный юнион с полем-тегом, а не набор булевых флагов: невозможные комбинации должны не компилироваться.

`any` запрещён. Для внешнего и недоверенного — `unknown` с сужением (в том числе в `catch`); когда тип зависит от вызывающего — дженерик.

## React

Разделяй контейнер и представление: контейнер владеет данными, состоянием и эффектами; презентационный компонент получает пропсы и рендерит, без запросов и сторов.

Состояние живёт максимально низко: `useState` в одном компоненте → lift к общему предку → Context только для редко меняющегося (тема, auth, локаль) → внешний стор для частых обновлений через дерево. Серверные данные — в server-state библиотеке (query-слой), не в состоянии приложения.

Выводимое из имеющегося состояния не хранится — вычисляется при рендере. `useEffect` для производного состояния — дефект.

`useEffect` — только синхронизация с внешней системой (подписка, браузерное API, сторонняя либа). Уведомление родителя и реакция на действие — в обработчике события, не в эффекте.

Каждая подписка, таймер и запрос в эффекте обязаны иметь cleanup. Deps — полные; `exhaustive-deps` не глушится без комментария-причины.

`key` списка — стабильный идентификатор, не index: при переупорядочивании index привязывает состояние детей к чужим строкам.

Компонент не определяется внутри другого компонента: новый тип на каждый рендер ломает reconciliation и размонтирует детей.

## Тестирование

Тестируется поведение через то, что видит пользователь: запросы по роли → лейблу → тексту, `data-testid` — последний выход. Внутренний state, пропсы детей и число рендеров не проверяются: рефакторинг без правки тестов — признак правильного теста.

Взаимодействие — через `userEvent` (с `await`); асинхронное появление — `findBy*` или `waitFor`, никогда `setTimeout` + проверка.

Сеть мокается на сетевой границе (MSW и аналоги), а не подменой хуков и модулей данных.

Снапшоты рендера компонентов не пишутся — хрупкие и не читаются на ревью. Визуальная регрессия — скриншотными тестами (в монорепо — PP/hermione).

Приоритет покрытия: чистые утилиты и хуки — плотно; контейнеры — happy path плюс состояния ошибок; страницы — smoke. Гнаться за процентом строк не нужно.

## Безопасность

`dangerouslySetInnerHTML` — стоп-сигнал: пользовательский HTML только через санитайзер (DOMPurify) в месте вызова, иначе рендер текстом.

URL из данных пользователя валидируется по схеме (http/https/mailto) перед подстановкой в `href`/`src`: `javascript:` и `data:` исполняют код, React их не блокирует. Внешняя ссылка с `target="_blank"` — всегда с `rel="noopener noreferrer"`.

Секреты не попадают в код и в публичные env-переменные: всё с префиксом `NEXT_PUBLIC_`/`VITE_`/`REACT_APP_` уезжает в бандл и читается любым посетителем.

Токены и сессии не хранятся в `localStorage` (доступен любому XSS). Скрытие UI по роли — не защита: доступ обязан проверять API, клиентский гейт лишь прячет кнопку.

## Перфоманс

По умолчанию не мемоизировать. `useMemo`/`useCallback` — только когда значение идёт пропсом в `memo`-ребёнка, стоит в deps другого хука или вычисление дорого по замеру профайлера. Лишняя мемоизация — шум и скрытые баги.

Независимые `await` не выстраиваются в цепочку — `Promise.all`; дорогая работа откладывается до ветки, где результат реально нужен. Waterfall — главный убийца загрузки.

Импорты — прямые из модуля, не через barrel `index.ts`; тяжёлый и редко нужный компонент — динамическим импортом с фолбеком.

Подписка на стор — на производное значение (`s.cart.length > 0`), не на сырой объект; значение, нужное только в колбэке, читается в момент вызова, а не подпиской. Новый объект/массив в пропсах и deps на каждый рендер — ломает memo, выноси в константу.

Оптимизация начинается с профилирования: без замера «медленно» — гипотеза, а не факт.

## Оркестрация работы

Крупная задача идёт фазовым конвейером: RESEARCH → PLAN → IMPLEMENT → REVIEW → VERIFY. Фазы не пропускаются; ревью нашло проблему или verify упал — возврат на нужную фазу, а не патч поверх.

Результат каждой фазы — файл (research-summary, plan, review-notes), вход следующей фазы — этот файл, а не память диалога: контекст сессии теряется, файл — нет.

Один субагент — один вход и один выход. Субагенту передаётся цель задачи, а не только буквальный запрос; его результат оценивается и при нехватке дозапрашивается, прежде чем лечь в основу следующей фазы.
