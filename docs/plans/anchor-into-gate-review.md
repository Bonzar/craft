# Находки обкатки

Что нашли критики до показа плана и ревью-бот на самом PR. Держу рядом с планом: без этого следующая сессия пойдёт по тем же граблям, а половина находок в план не попала дословно — только результатом.

## Обкатка плана (четыре критика, первый проход)

Прошёл целиком. Второй проход не состоялся — кончился дневной лимит клиента на середине.

- Дыра шире `rm`: гвард якоря отвергал по имени команды и держал `touch`, `mkdir`, `chmod`, `ln`, `dd`, `truncate`, `git checkout --`, `git clean`. Разбор целей записи не видит ни одной. Отсюда весь разворот замысла.
- `mv README.md /tmp/x` даёт только цель-назначение: исчезновение файла из репозитория не видно.
- `rm -rf node_modules` эфемерным не является: `node_modules` в игноре этого репозитория не значится.
- Снятие ветки гварда роняет набор в двух местах раннера: требование исхода `session-anchor:deny` и смоук маршрута `universal-session-anchor / PreToolUse / Bash`.
- Кейсы гейта после переезда начнут зеленеть отказом якоря вместо того, что проверяют: отказ есть отказ, подмены не видно. Нужен сеятель якоря.
- Приёмка «отказ по якорю» одним `deny` не выражается: нужен составной признак — отказ гейта И слово «якорь» в тексте.
- Выходы правила (автономка, замер, вложенный вызов, пустой идентификатор сессии) на пустом реестре тривиально зелёные: проверять их надо на засеянном.
- Поверхности гейта шире гварда: пишущий подагент и незнакомый MCP-инструмент кейсами не покрыты.
- Правило «Задача-якорь сессии» правится через скилл «Обслуживание памяти» — это подстраница роутера.
- Комментарии, описывающие старое устройство: шапка классификатора, комментарий про широкий матчер в таблице маршрутов, кусок про якорь в инжекторе правил общения, разделы README.

## Ревью-бот на PR

Обе находки приняты, план поправлен.

- **Признак мутации нельзя брать из предиката чтения.** Правила чтения консервативны: `sed -e`, `sed -f`, `awk -f` помечены запрещающими флагами, хотя файлы на месте меняет только `-i`. Взяв «не доказано чтение» за признак записи, инструмент потребовал бы якорь и сверку на обычном `sed -e 's/x/y/' файл`. Нужен свой точный список команд, меняющих дерево, с извлечением их путей.
- **Временная цель обязана перекрывать имя команды.** У `rm /tmp/f` разбор целей молчит, а имя опознано как изменение состояния: по правилу «достаточно любого признака» инструмент ответил бы «пишет» и запер уборку временных файлов. Значит список мутаторов обязан отдавать свои цели, и решение принимается по ним.
