# Start owner Visual live before drawing
After verifying the existing owner session and trusted capabilities, bootstrap starts the existing live transport before doing any WebGL/graph work. The first valid hello plus initial reset catch-up, both bound to the database epoch, start the initial manifest and one queue page concurrently. The selector-specific graph manifest, packed binaries and queue remain existing same-origin, owner-authenticated resources. An epoch mismatch never reaches the rendered state. The badge becomes Live only after separated hello and heartbeat frames and an accepted graph. If no real stream authority arrives in 1.5 seconds, render an ordinary same-origin snapshot, not a fabricated Live badge. A clear invalidates the prior epoch; normal reconnect keeps the current context without reloading.

The existing signed TEST public-IP path carries no private graph/queue payload. The ordinary variant is available on existing authenticated same-origin GET /api/v1/events without query only with explicit startup owner_snapshot_events opt-in (CLI --owner-snapshot-events, off by default). The same path with established selector/revision stays backwards-compatible. Bridge-only credentials are not owner browser credentials. No ingress or runtime profile is changed by this source change.

A future same-origin-only stream could carry a small initial manifest and/or queue envelope with pagination and body caps, owner/cookie and generation fences, private no-cache responses, bounded event sizes and proxy flush proof. Large graph binaries and queue pagination should not be SSE frames. This implementation sends authoritative scope/refresh metadata and reads the bounded snapshot through existing endpoints. Verify public edge flush independently from a local WebKit fixture.
