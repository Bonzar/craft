# /save-session — память код-сессии

Записать состояние работы в файл, читаемый будущей сессией через
`/resume-session`. Когда: конец рабочей сессии, перед упором в лимит контекста
(сначала сейв, потом `/compact` или новая сессия), после решения сложной
проблемы, при передаче работы.

## Куда

Файл: `~/.claude/session-data/<слаг-проекта>-<YYYY-MM-DD>.md`.

- Слаг — имя директории репозитория (для worktree — имя основного репо),
  например `craft-local-2026-07-27.md`. Папку создать при отсутствии:
  `mkdir -p ~/.claude/session-data`.
- Файл на эту дату уже есть — дополнить/переписать его актуальным состоянием
  (одна сессия-день — один файл), к чужим датам не дописывать.

## Перед записью — собрать факты

- `git status` / `git diff --stat` (или `arc status/diff`) — фактически
  затронутые файлы, не по памяти диалога.
- Статус проверок на момент сейва (typecheck/тесты) — если гонялись.

## Формат файла — четыре секции обязательны

Секции ниже пишутся всегда; нечего писать — честное «пока ничего», секцию
не выкидывать. Пустая честная секция лучше пропущенной.

```markdown
# <слаг-проекта> — YYYY-MM-DD

**Задача:** одно предложение — над чем сессия работала и зачем.

## Что сработало (с доказательством)
Только подтверждённое. У каждого пункта — ЧЕМ подтверждено: прошёл тест
(команда), увидел в браузере, ответ 200. Без доказательства — пункт
переезжает в «не пробовали».
- <что> — подтверждено: <чем>

## Что пробовали и не сработало
Самая ценная секция: без неё следующая сессия повторит тупики.
У каждого пункта — ТОЧНАЯ причина: текст ошибки, почему подход
несовместим. «Не взлетело» — не причина.
- <подход> — упало: <точная причина>

## Что не пробовали / осталось
Идеи и подходы из обсуждения, до которых не дошли; оставшиеся куски работы.
Конкретно настолько, чтобы следующая сессия начала без раздумий.
- <подход / кусок работы>

## Следующий шаг
Один самый важный шаг при возобновлении, с файлом и действием. Не определён —
так и написать: «шаг не определён — начать с ревизии секции „не пробовали"».
```

По необходимости — необязательные секции: «Состояние файлов» (файл → статус),
«Принятые решения» (решение → почему), «Блокеры», «Окружение» (нестандартный
запуск, env).

## После записи

Показать содержимое Владу и спросить, точно ли отражено — поправить по ответу.

Смежное: PreCompact-хук автоматически пишет
`~/.claude/session-data/precompact-*.md` перед компактом — это аварийная
страховка, а не замена `/save-session`: осознанный сейв точнее и структурнее.
