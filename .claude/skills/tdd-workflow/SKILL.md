# TDD: red → green → refactor

Суть: тест пишется ДО кода и обязан упасть по задуманной причине. Тест, который
никогда не падал, ничего не доказывает.

## Когда применять / не применять

**Применять:** новая логика (утилиты, хуки, модели, редьюсеры, API-слой),
багфикс (сначала тест-репродьюсер), рефакторинг с изменением поведения.

**Не применять:** вёрстка и визуал (в Аркадии это PP-скрины и testplane — свой
цикл, см. скилл frontend-visual-tests), конфиги и инфраструктура, спайк на
выброс, правка текстовок. Там тесты — по здравому смыслу, не по ритуалу.

## Раннер по мирам

- **Аркадия:** jest — `npm run jest` / `npx jest <путь>` из директории проекта
  (@crm/*). e2e/скрины — testplane, в TDD-цикл юнитов не входят.
- **Личные GH-проекты:** `package.json` → `scripts.test` (jest или vitest);
  не угадывать — посмотреть перед первым запуском.

## Цикл

1. **RED.** Написать тест на целевое поведение и запустить. Валиден только
   если: тест реально выполнился, упал, и причина падения — именно отсутствие
   реализации или сам баг (не опечатка в сетапе, не сломанный импорт).
   Пока RED не подтверждён — production-код не трогать.
2. **GREEN.** Минимальная реализация, чтобы тест прошёл. Не писать «заодно»
   лишнего — лишнее не покрыто тестом.
3. **REFACTOR.** Улучшить код при зелёных тестах: имена, дубли, структура.
   После — перегнать тот же тест-таргет.
4. Для багфикса: репродьюсер остаётся в сьюте как регресс-тест навсегда.

## Что тестировать

- Поведение, видимое пользователю кода, а не внутренности:
  `getByText`/`getByRole` вместо `component.state`, результат функции вместо
  порядка внутренних вызовов.
- Краевые случаи: пустое, null, большие объёмы, ошибка зависимости.
- Каждый тест независим: свой сетап, без опоры на порядок выполнения.
- Один тест — одно поведение, имя описывает его словами.

## Грабли

- «Написал тесты и код одним заходом, всё зелёное» — RED-гейт пропущен,
  тесты могут проверять ничего. Откатить реализацию мысленно: упал бы тест?
- Мокать границы (сеть, время, fs), а не собственную логику — замоканная
  своя логика превращает тест в тавтологию.
- Проверка покрытия — по месту: в Аркадии покрытие гоняет CI, локально
  достаточно прогнать затронутые сьюты.
