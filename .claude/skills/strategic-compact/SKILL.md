# Стратегический компакт

Авто-компакт срезает контекст в произвольной точке — часто посреди задачи,
теряя имена файлов и промежуточное состояние. Правильный момент — граница фаз,
когда объёмный контекст уже дистиллирован в план или результат.

## Когда компактить

| Переход | Компакт? | Почему |
|---|---|---|
| Исследование → план | да | сырьё разведки объёмно, план — его выжимка |
| План → реализация | да | план зафиксирован (todo/файл), контекст под код |
| Отладка → следующая фича | да | трейсы отладки — шум для новой работы |
| Провальный подход → новый | да | тупиковые рассуждения мешают свежему заходу |
| Реализация → тесты той же фичи | по месту | тесты опираются на свежий код — часто лучше не компактить |
| Посреди реализации | нет | потеря путей, имён и частичного состояния дорога |

## Перед компактом — сохранить

Компакт переживают: файлы на диске, git-состояние, CLAUDE.md, todo-список.
Теряются: прочитанное содержимое файлов, ход рассуждений, устные уточнения.

Поэтому до компакта: важное состояние — в файл или `/save-session`
(незаменимые находки, что не сработало, следующий шаг). PreCompact-хук
дополнительно пишет `~/.claude/session-data/precompact-*.md` — но это
страховка, а не замена осознанного сейва.

## Как

`/compact` с фокус-сообщением, что держать: `/compact дальше — реализация
X по плану выше`. Без фокуса компакт сожмёт равномерно и может утопить главное.
