# Онбординг в кодовую базу

Понять проект структурно за минимум чтения. Итог — короткий гайд в чате;
CLAUDE.md этот скилл не пишет (для него — встроенный `/init`).

## Фаза 1: разведка (Glob/Grep, не Read всего подряд)

Параллельно собрать сигналы:

- Манифест: `package.json` (workspaces? packageManager? scripts), lockfile.
- Фреймворк: next/vite/webpack-конфиги, `tsconfig.json`.
- Точки входа: `index.*`, `main.*`, `app.*`, `src/`.
- Дерево: верхние 2 уровня без `node_modules`, `dist`, `.git`.
- Тулинг: eslint/prettier-конфиги, CI (`.github/workflows/`, a.yaml в Аркадии),
  Makefile, Dockerfile.
- Тесты: `*.test.*`, `*.spec.*`, `*.hermione.ts`, jest/testplane-конфиги.
- В монорепо Аркадии: свой пакет (@crm/*) — граница разведки, соседние пакеты
  смотреть только по импортам из своего.

## Фаза 2: карта архитектуры

Из сигналов зафиксировать:

- **Стек:** язык/версии, фреймворк, стейт-менеджмент (mobx? rx?), сборка, CI.
- **Паттерн:** монолит / монорепо / фронт+бэк; стиль API (REST, GraphQL).
- **Директории:** верхний уровень → назначение, только неочевидные
  (`src/` пояснений не требует).
- **Поток данных:** протрассировать один сценарий от входа до результата —
  где роутинг, где валидация, где бизнес-логика, где данные.

## Фаза 3: конвенции

- Нейминг файлов и компонентов, схема тест-файлов.
- Обработка ошибок, паттерны асинхронщины, DI или прямые импорты.
- Git: стиль коммитов и веток из недавней истории (истории нет — так и сказать).
- Не угадывать: конфиг говорит одно, а код другое — верить коду.

## Грабли

- Не читать всё: разведка — Glob/Grep, Read точечно по неоднозначным сигналам.
- Не пересказывать README — гайд даёт структурный срез, которого в README нет.
- Не перечислять все зависимости — только формирующие стиль кода.
