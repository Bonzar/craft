# Вендоренные скиллы

Скиллы из чужих наборов, скопированные в репо файлами. Приезжают чекаутом — ни
утилиты, ни локфайла не требуют. Файлы лежат в `.claude/skills/` вперемешку со
своими.

**Префикс источника обязателен.** Папка называется `‹владелец›-‹скилл›` по
владельцу репозитория, и то же имя ставится в поле `name` — иначе в списке
скиллов чужое неотличимо от своего, а реестр в этот момент никто не читает.
Префикс в `name` — сознательное отклонение от upstream, оно всегда есть и всегда
одно и то же.

**Больше не правим.** Всё остальное в файле — копия upstream: наша правка ломает
чистый дифф при обновлении. Нужно другое поведение — это решение Влада, и оно
записывается в колонку «отклонения» рядом с префиксом.

**Лицензия едет вместе со скиллом.** Рядом с `SKILL.md` кладётся копия лицензии
источника под именем `LICENSE.‹владелец›-‹репозиторий›` — MIT и подобные требуют
этого при распространении, а имя с суффиксом не даёт спутать её с лицензией
нашего кода.

**Берём только то, что работает у нас.** Служебные файлы чужого набора для других
интерфейсов (например `agents/openai.yaml`) не копируются; что именно опущено —
в колонке «отклонения».

**Берём по коммиту, не по ветке.** Файл тянется по зафиксированному коммиту,
дифф при обновлении считается от него же. Иначе «дословная копия»
невоспроизводима.

| Скилл | Источник | Upstream-путь | Коммит | Дата | Лицензия | Отклонения |
|---|---|---|---|---|---|---|
| `mattpocock-grilling` | github.com/mattpocock/skills | `skills/productivity/grilling/SKILL.md` | `84fdeffd12f2ee307994d1eb6feb48173b6e0502` | 2026-08-12 | MIT | `name` префиксован; `agents/openai.yaml` не взят; добавлен файл лицензии |

Обновление: взять файл по новому коммиту, вернуть префикс в `name`, сверить
лицензию источника, посмотреть дифф, обновить коммит и дату. Наберётся
три-четыре скилла — перейти на утилиту `skills` с выборочной установкой.

Порядок для вендоренных ДАННЫХ — там, где они лежат: `modules/shell-tree/data/README.md`.
