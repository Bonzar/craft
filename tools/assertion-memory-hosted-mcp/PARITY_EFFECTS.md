# Common environment effect transport

Build one canonical catalog from an independently pinned release, then retain canonical MCP schemas and build audited capability projections. Both environments use these exact same policy, ASGI and Worker bytes. Runtime configuration alone fixes lane, site/gateway origin, matching canonical release/catalog, pinning authority, credential scope and opt-in flag. Effectless profiles retain the former catalog digest; when enabling projected effects the existing read route continues to require the prior read digest. No endpoint accepts a caller-selected lane.

Both projected effects reuse the same existing canonical handlers. Only capture_message and process are admitted; query/generation and unrelated mutations remain absent. Profiles require distinct Read and Effects credentials and a private owner verifier. Both lanes default to no effects if no explicit environment-specific flag/configuration exists. No production host is provisioned by this change. The existing TEST-only host qualification harness remains separate from eventual shared host profiles.

Offline source proofs: python -B -m unittest test_test_effects and node test_test_effects.mjs. These exercise route, token, owner mismatch, effect-only split, canonical schema equality and no-upstream denials; no database or synthetic capture is used. For existing exact private TEST v22, stage_test_effects.py re-assembles the same three-file overlay from its approved source and preserves native metadata and owner gate. Prod may not go live until its separate host/owner attestation and the selected immutable release catalog are independently proven.
