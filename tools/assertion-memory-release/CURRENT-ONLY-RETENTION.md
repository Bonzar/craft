# Current-only generated release builds

Base TEST/PROD and both **packed Visual** lanes call current-only retention in
the normal receiver, behind one host-bootstrap marker per scope. It is not an
external scheduled delete, age policy, or global filesystem collector.
Authenticated legacy static-only deploy and the separate legacy runtime switch
are not new automatic retention entry points.

| Scope | Canonical writer root | Eligible stores |
|---|---|---|
| base-test | /srv/assertion-release/test | releases/REVISION-PAYLOAD-DIGEST |
| base-prod | /srv/assertion-release/production | releases/REVISION-PAYLOAD-DIGEST |
| visual-test | /var/lib/assertion-memory-visual/test | releases/MANIFEST-DIGEST, runtime/versions/RUNTIME-DIGEST |
| visual-prod | /var/lib/assertion-memory-visual/prod | releases/MANIFEST-DIGEST, runtime/versions/RUNTIME-DIGEST |

On admission the receiver holds the same deployment lock, resolves settled
pointers and safely sweeps exact inactive builds before allocating the new
archive/venv. Packed Visual does this before the already signature-verified
static frame is spooled, and repeats the settled check under the actual joint
writer lock before preparing. Base's reserve is 768 MiB and Visual's is 32 MiB
plus 1,024 inodes; a shortfall fails before archive unpack. Two writer locks
are held for packed Visual when its old runtime-only lock is installed.
For Base PROD's proof/unlink the receiver nonblockingly takes a shared
legacy transition fence; the root witness refuses outstanding permit/pending
markers. The fence is never held by retention across restart/prepare/smoke.
Neither the prior nor unverified new build is pruned while a rollback journal
exists. After committed activation and exact smoke it repeats the sweep while
the lock is still held. A failed prepare/recovered activation tries only its
exact unactivated candidate and never the prior active build. Failed cleanup
is reported, not passed off as success or used to fabricate rollback.

Preflight and postcommit log counts: removed, unproven, unknown. Paths and
exception details are not logged. Unproven means no positive independent
proof or exact provenance. Legacy runtime folders without a generated byte
receipt, foreign shapes, symlink roots, inode/device or manifest drift, busy
processes, unknown mounts and journals are not swept. If a killed prepare left
a real artifact with the original verified manifest, the next run can
reconsider it; if ordinary proof still cannot qualify it, explicitly inventory
that exact residue. No DB, WAL, wheels/offline wheelhouse, credentials, config,
logs or backups are candidates. A live or interrupted deployment always takes
priority over cleanup.

## One-time host bootstrap (not run by application archives or this document)

1. Compare and pin the GitHub merged source for the shared **host**
   release_core.py, base_payload.py, release_retention.py,
   retention_authority.py and per-lane Visual runtime_joint.py,
   runtime_receive.py, runtime_host.py. An application archive does not
   change the trusted receivers under /etc. Use reviewed configuration
   management/root install under the PROD transition fence and all canonical
   lane locks, with exact prior receiver modules retained until import and
   forced-command probes pass. The systemd templates in retention-systemd/
   use the four existing account groups; verify effective groups before use.
2. Prove that the running and restartable host service inventory for each lane
   only uses that lane's physical active build or trusted paths outside these
   stores (including separately running Graph/Sites-facing wrappers, worker
   children and their launchers). Prove all host PIDs, task FDs, mount namespaces
   and lock records are observable by the root witness. **Do not guess these
   from four main PIDs**. Install the current-only Visual origin first: signed
   owner current document/assets succeed, retired HTML navigation redirects to
   /visual, retired JS/CSS/worker gives 404 and never HTML; legacy asset relay
   also refuses stale digests. The live Visual process must authenticate its
   current-only capability and exact entry/static identity before sweeping.
   Rolling back to a pre-policy Visual release restores normally and defers
   cleanup while that active origin lacks the capability. If any deployment
   still routes readers to
   historical releases, leave that lane dark.
3. Put a root-owned 0600 /etc/assertion-release-retention/SCOPE.json with exact
   JSON {"scope":"SCOPE","uid":ACTUAL_DEPLOY_UID,"host_complete":true,"current_only":true,"pins":{ABSOLUTE_LAUNCHER_PATH:SHA256,...}}
   in a root-only writable directory. Pin the actual authorized effective
   systemd fragments, all drop-ins, and applicable launch wrappers as inspected
   for that scope. The witness rejects changed bytes/modes and rechecks them
   after the host scan. Start only that scope's reviewed socket.
   Neither a marker nor data from a caller grants permission by itself: peer
   credentials, actual writer lock FD, scoped active pointer, exact target
   inode, and independent stable host-wide no-reference/mount witness must all
   agree. Witness never deletes anything and does not emit proc contents.
4. Before enabling, use scoped release_retention.dry_inventory(scope, stores)
   from the exact installed modules as the canonical deploy UID (Base store uses
   base_payload.retention_candidate; packed Visual stores use
   runtime_joint.retention_static and retention_runtime, plus an exact
   authenticated runtime_host.retention_reader_ready callback). This opens only
   existing lock files and invokes the live witness without any unlink; compare
   the would_remove count with trusted deployment history and rollback
   reachability. Also test denial on a known busy candidate and independent
   transfer/smoke in TEST. Do not auto-enable because an offline test passed.
5. With TEST satisfactory on the protected release path, enable the exact
   root-owned unshared 0644 SCOPE.enabled file containing on followed by a
   single newline. Subsequent normal jobs perform the hooks automatically.
   Check logs for any deferred cleanup, exact ports/site health, new pointers,
   and fixture DB unchanged. Repeat scope qualification and standard protected
   PROD approval for prod. Disable future new receiver retention by removing
   only that exact marker via approved operator path; don't move running
   releases.

## Rollback is a new protected deployment

The live rollback pair exists until the current transaction's verified smoke.
An operational rollback later selects an immutable GitHub source tag/commit
and goes through protected TEST then PROD with the same archive. Existing
controllers replay the exact original GitHub Actions artifact only while that
artifact is available; a source ZIP or tag cannot replace it, and existing
immutable Releases have no attached runtime assets. Beyond that retention
window use a separately reviewed protected rebuild controller, pinned current
trusted builder and exact compatible older source, with its freshly bound
artifact digest and new same-run TEST proof. Do not imply all historical tags
are currently redeployable after Actions artifact expiry. Verify at least
one independent compatible prior GitHub version before arming the first
host scope. Preserve unknown local residues rather than treat them as usable
rollback copies or quietly delete them.
